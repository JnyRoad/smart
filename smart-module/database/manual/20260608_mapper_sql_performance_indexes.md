# MyBatis SQL Performance Indexes

执行用户：`TECH_PLATFORM`

说明：

- 本文件只提供手工执行的 Oracle 索引 DDL，不包含任何生产对象缺失处理。
- 执行前先确认索引名未被占用；如已有同等前缀列索引，不要重复创建。
- 建议在低峰期执行，并在执行后收集统计信息。

## P0

### 电表历史查询

`SMT_ELE_METER_HISTORY` 当前生产数据量约 15,734,672 行，`ELE_METER_ID + COLLECT_TIME` 查询缺少组合索引。

```sql
CREATE INDEX IDX_ELE_HIS_METER_TIME
ON SMT_ELE_METER_HISTORY (ELE_METER_ID, COLLECT_TIME);
```

### 车辆抓拍查询

`SMT_SNAP_VEHICLE` 当前生产数据量约 1,560,886 行，生产库未查到普通查询索引。代码已把 `SNAP_TIME` 列端函数改为范围比较，下面索引用于支撑园区、事件、设备维度的时间范围查询。

```sql
CREATE INDEX IDX_SNAP_VEH_PARK_EVT_TIME
ON SMT_SNAP_VEHICLE (PARK_ID, EVENT_TYPE, SNAP_TIME);

CREATE INDEX IDX_SNAP_VEH_DEV_TIME
ON SMT_SNAP_VEHICLE (DEVICE_ID, SNAP_TIME);
```

### ISC 设备任务队列

`SMT_ISC_DEVICE_TASK` 当前生产数据量约 2,758,966 行。代码已把待处理谓词统一为 `NVL(STATUS, 0) = 0`、`NVL(CODE, -1) != 200`，下面为对应函数索引。

```sql
CREATE INDEX IDX_ISC_DEV_Q_START
ON SMT_ISC_DEVICE_TASK (
  DEVICE_TYPE,
  NVL(STATUS, 0),
  ACTION,
  START_TIME,
  TIMES,
  NVL(CODE, -1)
);

CREATE INDEX IDX_ISC_DEV_Q_OVER
ON SMT_ISC_DEVICE_TASK (
  DEVICE_TYPE,
  NVL(STATUS, 0),
  ACTION,
  OVER_TIME,
  TIMES,
  NVL(CODE, -1)
);
```

### 旧设备任务队列

`SMT_DEVICE_TASK` 当前生产数据量约 1,717,812 行。代码已把部分待处理谓词改为 `NVL(STATUS, 0) = 0`、`NVL(CODE, -1) != 200`，删除任务仍保留 `STATUS = 0` 语义。

```sql
CREATE INDEX IDX_DEV_TASK_Q_START
ON SMT_DEVICE_TASK (
  DEVICE_TYPE,
  NVL(STATUS, 0),
  ACTION,
  START_TIME,
  TIMES,
  NVL(CODE, -1)
);

CREATE INDEX IDX_DEV_TASK_Q_OVER
ON SMT_DEVICE_TASK (
  DEVICE_TYPE,
  STATUS,
  ACTION,
  OVER_TIME,
  TIMES,
  NVL(CODE, -1)
);
```

## P1

### 人员抓拍查询

`SMT_SNAP_PERSON` 当前生产数据量约 5,659,533 行。代码已把 `SNAP_TIME` 列端函数改为范围比较，下面索引用于人员类型、园区、事件、时间组合查询。

```sql
CREATE INDEX IDX_SNAP_PER_TYPE_TIME
ON SMT_SNAP_PERSON (PERSON_TYPE, PARK_ID, EVENT_TYPE, SNAP_TIME);
```

### 工资签单查询

`SMT_WAGE_SIGN` 当前生产数据量约 1,242,111 行，生产库未查到普通查询索引。代码已把 `WAGE_DATE LIKE '%...%'` 改为等值匹配，并把 `CREATE_TIME` 列端函数改为范围比较。

```sql
CREATE INDEX IDX_WAGE_SIGN_QUERY
ON SMT_WAGE_SIGN (WAGE_DATE, SIGN_STATUS, BADGE, CREATE_TIME);
```

### 考勤签单查询

`SMT_ATTENDANCE_SIGN` 当前生产数据量约 1,104,449 行，生产库只查到 `ID` 唯一索引。

```sql
CREATE INDEX IDX_ATT_SIGN_QUERY
ON SMT_ATTENDANCE_SIGN (CHECK_DATE, SIGN_STATUS, BADGE, CREATE_TIME);
```

### 消息记录查询

`SMT_MSG_RECORD` 当前生产数据量约 1,220,222 行，生产库只查到 LOB 索引。代码已修复 `read_state` 错误别名。

```sql
CREATE INDEX IDX_MSG_REC_QUERY
ON SMT_MSG_RECORD (MSG_OBJECT, DELETE_STATE, READ_STATE, CREATE_TIME);
```

## P2

### 员工查询

`SMT_STAFF` 当前生产数据量约 370,448 行。代码已把 `CREATE_TIME` 列端日期/月度函数改为范围比较。

```sql
CREATE INDEX IDX_STAFF_CREATE_STATUS
ON SMT_STAFF (CREATE_TIME, STATUS);

CREATE INDEX IDX_STAFF_COMP_DEP_CREATE
ON SMT_STAFF (COMP_ID, DEP_ID, CREATE_TIME);
```

如必须保留 `LOWER(BADGE) = LOWER(:badge)` 的大小写不敏感查询，再补下面这个函数索引；如果员工工号统一大写且调用方已规范化，可以不建。

```sql
CREATE INDEX IDX_STAFF_BADGE_LOWER
ON SMT_STAFF (LOWER(BADGE));
```
