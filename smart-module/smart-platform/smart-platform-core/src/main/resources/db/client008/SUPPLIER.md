# 供应商通行 Oracle 持久化资源

`V002__supplier.sql` 只创建规格 008 供应商通行使用的四张独立业务表：

- `SMT_CLIENT_SUP_PRESENCE`：按人员和区域保存明确建立的在内状态与版本。
- `SMT_CLIENT_SUP_VERIFY`：保存短时核验及一次性消耗状态。
- `SMT_CLIENT_SUP_EVENT`：保存独立进出事件，并限制同一核验和同一人员区域版本只能产生一个事件。
- `SMT_CLIENT_SUP_COMMAND`：保存作用域、操作人和幂等键对应的请求摘要与原始回复。

`V003__supplier_unknown.sql` 只扩展人员区域状态和核验快照的两个状态约束，使其允许
`UNKNOWN`。首次核验会先通过当前资格、执行权限、岗位和区域规则，再以 `UNKNOWN/0`
建立缺失的人员区域状态；首次明确进入或离开事件才确定 `INSIDE` 或 `OUTSIDE`。旧
`verify` 入口仍拒绝缺少基线的人员，不会把未知状态推断为在外。

仓储可按核验编号恢复内部核验对象，并按调用方传入的授权岗位集合读取事件。事件查询始终
限制岗位范围，按发生时间和事件编号稳定降序，单次只允许 1 到 100 条；空岗位集合直接返回
空结果。HTTP 适配在返回人员快照前仍须校验当前操作人与岗位绑定。

应用不会自动执行本资源。生产应用前须另行核实目标 Oracle schema、版本兼容性、现有对象、变更窗口、备份与回滚，并取得对应授权。

显式启用的本机 Oracle 集成测试只允许连接规格 008 的 `SMART_CLIENT_008@FREEPDB1`，先核对产品、schema、PDB 及四张目标表。目标表全部不存在时，测试辅助代码可以在该已授权本机 schema 依次应用 V002 与 V003；已有 V002 精确结构时只在两个旧状态约束均未扩展的情况下应用 V003，部分迁移或结构不匹配时必须失败。测试只删除本轮唯一前缀的合成数据，不删除表、schema、数据卷或其他任务数据。

生产环境的历史通行迁移尚未设计。新首次核验入口只建立 `UNKNOWN/0`，不默认创建 `OUTSIDE/0`，也不提供厂牌、资格、账号或第三方系统的模拟来源。
