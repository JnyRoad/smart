# 门锁 Web 复刻实施计划

## 前置原则

第一版按 WEB-L-001 至 WEB-L-008 的旧后台页面组交付。页面可以内部复用现有 Smart 组件，但不能删减、合并或改名到管理员无法完成旧有操作的程度。旧接口和旧服务均不进入新页面运行链路。

## WBS

| ID | 任务 | 交付与验收 |
|---|---|---|
| UIW-001 | 冻结旧运行态证据包。 | 完成 legacy-reference 中的菜单、页面、交互、导出和禁用证据；未取得项保持 OPEN-008。 |
| UIW-002 | 冻结组件、菜单和资源码映射。 | WEB-L 每页确定 component 值、菜单层级、权限码、园区数据范围、旧链接兼容方式。 |
| UIW-003 | 建立 smart-ui/src/api/lock/。 | 以新 smart-lock API 的领域 DTO、错误码、分页和命令状态为唯一入口；无页面直连旧服务。 |
| UIW-004 | 实现 WEB-L-001。 | 锁卡片、详情四页签、远程开门状态和配置对版。 |
| UIW-005 | 实现 WEB-L-002。 | 设备查询、编辑、解绑、启停和管理员密码的受控操作。 |
| UIW-006 | 实现 WEB-L-003。 | 网关准入/关联设备和型号 CRUD。 |
| UIW-007 | 实现 WEB-L-004。 | 人员/卡/密码、员工查询、导入导出和敏感信息保护。 |
| UIW-008 | 实现 WEB-L-005、WEB-L-006。 | 授权变更、批量目标、命令结果查询和真实设备确认状态。 |
| UIW-009 | 实现 WEB-L-007、WEB-L-008。 | 记录/日志、告警/设置、导出、JSON 查看和批量处置。 |
| UIW-010 | 整理现有宿舍门锁重复入口。 | 仅在所有对版、菜单迁移、历史链接和培训验证后提出合并/重定向/下线 PR；本任务不授权删除旧页面。 |
| UIW-011 | 自动化与可访问性。 | 页面单测、E2E、错误/加载/弱网、园区越权、敏感字段、键盘可用性。 |
| UIW-012 | 对版签收。 | 按 parity-acceptance 形成每页旧/新证据和安全差异清单，关闭或保留 OPEN-008。 |

## 推荐实施顺序

1. UIW-001 至 UIW-003；
2. WEB-L-001、WEB-L-002、WEB-L-003，先建立设备、网关、型号和菜单骨架；
3. WEB-L-004、WEB-L-005、WEB-L-006，接入授权和可靠命令状态；
4. WEB-L-007、WEB-L-008，补齐记录、告警和设置；
5. UIW-010 至 UIW-012，统一回归和对版。

## 依赖与阻断

- smart-lock 的 API-002、权限码、错误码、分页合同和命令状态尚未实现前，只能用契约 mock 开发页面。
- WEB-L-001 的远程开门、WEB-L-002 的管理员密码、WEB-L-003 的网关准入、WEB-L-005 的授权和 WEB-L-008 的告警处置，都依赖实际设备状态与审计能力，不能用前端假成功代替。
- 厂商能力、敏感凭据、动态菜单运行态和旧页面细节未核实前，相关控件必须标为待核验或受控不可用。
