## 路由与菜单事实

- 旧 Web 在登录后请求 GET /menu，由 AvueRouter.formatRoutes 动态注册组件。离线包不能证明某一生产环境的最终菜单名称、排序、URL、资源码或隐藏状态。
- 可直接确认的旧静态详情跳转为 /lock/lockList/detail?id=设备标识。
- Smart 当前后台也由 GET /admin/menu 返回动态菜单，并按 sys_menu.component 懒加载页面。因此新页面必须同时完成组件路径、菜单数据、资源码、园区数据权限和导航验收。

## 首批运行态证据（FCT-016，2026-08-04）

《裕同科技精密智能锁系统网关设备注册操作手册》内嵌了 3 张旧后台运行态截图，是目前唯一的运行态证据。**版本为 2022 年、数据为线上测试的单条记录，不足以关闭 OPEN-008**，但已可修正数处此前的推测。

**网关列表（已确证）**：筛选为设备ID、设备名称、设备状态；表格列为设备ID、设备名称、IP地址、服务端口、设备状态、备注、操作；行操作为「允许入网」「禁止入网」「编辑」「连接设备」。与 WEB-L-003 描述一致，但**旧版未见「删除」行操作**——该项此前为推测，需再核。

一处语义陷阱：列头「服务端口」显示的其实是网关连过来的 **TCP 源端口**（随机高位端口），并非网关配置中的服务端口。复刻时不要沿用这个会误导运维的列名与取值。

**设备列表（已确证）**：筛选为园区、设备ID、设备名称、设备位置、设备状态；表格列为设备ID、设备名称、设备位置、连接状态、备注、操作；操作列**只有「编辑」**。WEB-L-002 此前描述的「是否可用开关」列，以及解绑、启停、修改管理员密码、批量改密等入口**在该截图中均不可见**——可能是版本差异或角色权限差异，须在补证据时重点确认。

**门锁监控（已确证）**：筛选为园区、设备名称、剩余电量、设备状态；图例为「正常 / 断开 / 低电量」三色，并显示「当前园区电量阈值：N」；卡片含锁图片、名称、剩余电量与「开门」按钮。与 WEB-L-001 的描述**逐项吻合**，并证实电量阈值取自园区级告警配置。

## 运行态补证据清单

在宣称“页面操作一摸一样”之前，前端负责人须在经授权的旧系统运行环境中，按每个 WEB-L 页面组保存以下受控证据：

1. 菜单层级、文案、排序、页面 URL 和资源码导出或截图；
2. 初始态、查询态、空态、加载态、无权限态、错误态和分页态截图；
3. 每个写操作从点击、校验、确认到结果的录屏或步骤截图；
4. 导出、导入模板、失败清单、弹窗详情、禁用条件和二次确认文案；
5. 旧页面中敏感字段展示的原始行为。新页面若出于安全规则作脱敏，须记录“安全差异”，而不是静默改变；
6. 对应设备型号、账号角色、园区范围、数据时间和采集人。

这些材料只存入受控证据库，仓库中只登记版本、日期和结论；不得提交生产人员信息、密码、指纹模板、完整卡号、网关地址或会话 token。

## 不可复刻项

| 旧行为或信息 | 新系统处理 |
|---|---|
| 旧接口 /device、/person、/permissions 等 | 仅作为行为参照；改用版本化 smart-lock API。 |
| 旧 H5 远程开门中硬编码的人员标识 | 明确禁止；本人身份只能由登录态在服务端解析。 |
| 密码修改记录中的明文或可逆密码信息 | 新页面只显示类型、脱敏摘要、结果、时间和操作者。 |
| 未完成的指纹采集弹窗 | 显示“未开通”或不提供入口，待协议与合规 Gate 关闭后另行实现。 |
| 恢复出厂、管理员密码等高风险设备写操作 | 保留操作入口与确认层级的对版要求，但执行须由新后端权限、审计和设备确认状态机约束。 |
