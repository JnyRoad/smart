# 门锁 Web 操作对版与验收

## 验收口径

第一版通过的是“旧 Web 管理员操作可完成”的对版，不是对旧系统接口、明文展示、硬编码身份或安全缺陷的复制。每个 WEB-L 页面组须建立旧/新并排证据矩阵。

| 对比维度 | 必须相同或等效 | 允许的受控差异 |
|---|---|---|
| 导航 | 菜单可达、名称、层级、页面入口与返回路径。 | 动态菜单 URL/资源码可按 Smart 规则调整，但必须有旧新映射和重定向方案。 |
| 页面结构与视觉 | 页面标题、信息层级、卡片/表格布局、字段和列顺序、页签顺序、按钮位置、弹窗层级、状态图标和管理后台信息密度。 | 可为无障碍、敏感数据脱敏和现有 Element UI 约束做必要微调；不得借机重做为不同的操作模型。 |
| 查询 | 筛选条件、查询/清空、列表列、分页、空态。 | 数据源变为 smart-lock，字段名称可随 DTO 变化但业务含义不变。 |
| 写操作 | 按钮、表单字段、校验、二次确认、取消和结果查看路径。 | 成功语义必须升级为“已受理/待确认/已确认”，不得继续把 HTTP 成功当设备成功。 |
| 导入导出 | 前置条件、模板、失败清单、导出入口。 | 敏感列可删除/掩码，服务端生成和审计可加强。 |
| 详情 | 页签、字段分组、查看动作、JSON/关联记录入口。 | 原始报文、密钥、密码、指纹模板和完整卡号必须脱敏或不展示。 |
| 权限 | 按旧角色的可见/可操作差异。 | 最终由 Smart 资源码、园区数据权限和服务端状态机裁定。 |

## 每页最小证据

1. 旧页面菜单和初始页面截图；
2. 新页面对应截图；
3. 正常操作、取消、校验失败、无权限、加载、空态、后端错误和分页的截图或录屏；
4. 写操作的审计/命令状态截图；
5. 导出或导入的前置条件和结果证据；
6. 差异清单，注明“旧行为、原因、审批人、风险、是否影响操作完成”。

## 不可放行条件

- 任何 WEB-L 页面缺失旧版管理员可见的关键操作；
- 菜单或资源码未配置，导致页面不能由真实角色进入；
- 页面仍调用旧门锁服务、旧 MySQL 或协议桥；
- 明文密码、指纹模板、完整卡号、网关密钥、原始敏感报文进入页面、导出、日志或浏览器持久化；
- 远程开门、授权、撤权、网关准入等物理操作以“请求发送成功”冒充设备完成；
- 未建立旧运行态证据却声称视觉或交互完全一致。

## 回归

每次改动 smart-ui/src/views/platform/lock、facility、key、setting，或 smart-ui/src/api/lock、菜单/资源码、导入导出组件时，至少运行 WEB-L 受影响面的单测与 E2E，并重新检查上述敏感字段和命令状态断言。完整发布前执行全部 WEB-L-001 至 WEB-L-008 的受控对版。
