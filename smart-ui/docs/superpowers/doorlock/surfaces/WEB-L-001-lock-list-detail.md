# WEB-L-001 门锁列表与详情

## 目标与落点

旧页面为 views/platform/lock/lock_list/index.vue 与 detail.vue。建议在 smart-ui/src/views/platform/lock/lock_list/ 落地，详情保留旧版可确认的 query 语义：从列表进入详情时携带设备标识。实际菜单 URL 和 component 值以旧运行态与 Smart 菜单约定核验后冻结。

## 列表操作对版

| 项目 | 第一版要求 |
|---|---|
| 筛选 | 园区、设备名称、剩余电量、设备状态；状态至少区分断开与正常。 |
| 卡片 | 展示锁图片、名称、电量和状态。电量须结合园区阈值区分正常、低电量、断开，不把“无数据”伪装成正常。 |
| 进入详情 | 点击卡片进入同一设备的详情页；返回列表时保留原筛选与分页状态。 |
| 远程开门 | 设备离线时禁用。点击后遵循旧版文字节奏“开门 → 正在开门 → 开门完成”，但最终结果必须由新后端命令/设备确认决定；超时或失败显示明确状态，不能按固定两秒直接宣告物理开门成功。 |
| 空/错/加载 | 逐项保留可理解的加载、无数据、查询失败和数据陈旧提示。 |

## 详情四页签

| 页签 | 字段与操作 |
|---|---|
| 基本信息 | 设备 ID、名称、型号、位置、状态。 |
| 授权人员 | 工号、姓名、手机号、有效期、状态、创建时间；添加、编辑、删除、取消授权、重新授权。 |
| 事件记录 | 时间、事件类型、事件描述，以及与命令或设备状态的关联入口。 |
| 配置 | 音量高中低静音、防尾随 2 至 5 秒、双重验证、提示音/语音、硬件/固件版本、恢复出厂、保存、取消。 |

## 写操作安全差异

- 添加、编辑、取消/重新授权、保存配置、恢复出厂、远程开门均保留旧版入口和确认层级。
- 新页面必须把“操作已提交”与“设备已确认”分开呈现；恢复出厂和远程开门不得因为 HTTP 成功就显示完成。
- 恢复出厂、双重验证、防尾随等字段仅在型号能力矩阵已确认时可编辑；未知能力展示为不可用并保留原因。
- 授权人员中的电话与凭据只按权限显示最小必要信息；不得在页面状态、日志或浏览器缓存中出现密码或指纹模板。

## 历史接口证据

旧包可见 GET /device/page、POST /device/open/{id}、GET /warn/config/{parkId}、GET /device/{id}、GET /permissions/person/{deviceId}、POST /permissions/add/person、PUT /permissions/cancelAuth/{id}、GET /lkEventRecord/page、POST /device/config、POST /device/reset/{id}。这些不是新接口设计；具体映射以 smart-lock API-002 冻结为准。

## 验收

对每个页签录制至少一条正常路径和一条失败/禁用路径；远程开门必须覆盖离线禁用、已受理待确认、成功和失败/超时。旧页与新页的筛选、卡片状态、详情字段、页签顺序、动作入口和确认文案逐项签字。
