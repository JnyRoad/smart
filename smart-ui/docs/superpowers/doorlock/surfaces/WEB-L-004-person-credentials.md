# WEB-L-004 人员与凭据

## 目标与落点

旧页面为 views/platform/key/person/index.vue，建议目标为 smart-ui/src/views/platform/key/person/。该页是门锁凭据管理入口，不复制 Smart 人员主数据；它只能引用 smart-platform 的员工和园区事实。

## 查询、表格与基础操作

| 项目 | 第一版操作基线 |
|---|---|
| 筛选 | 园区、工号、姓名、手机号。 |
| 顶部操作 | 查询、清空、添加、导入、导出。导出前必须选择园区。 |
| 表格 | 工号、姓名、手机号、指纹、IC 卡、密码、所属园区、备注、人员来源（自建/同步）。 |
| 行操作 | 编辑、删除。 |

## 编辑与导入对版

| 环节 | 旧版可见行为 | 新版约束 |
|---|---|---|
| 员工查询 | 可按工号查询员工并回填。 | 只通过 smart-platform 的受权查询引用员工；不可创建第二份人员事实。 |
| 表单 | 园区、工号、姓名、6 位数字密码、手机号、卡号、备注。 | 密码采用受控输入，绝不回显/持久化；服务端判断可用凭据和设备能力。 |
| 改密码 | 编辑时密码变更会询问是否重新下发。 | 保留确认语义，结果显示为命令状态而非立即完成。 |
| 导入 | 必须先选择园区，可下载模板并查看失败名单。 | 模板、行级失败和重试均由新 API 支持；导入文件不得包含指纹模板。 |

旧包中的指纹采集弹窗是未完成占位。第一版不假装能够采集/下发指纹；待生物特征合规、设备协议和采集链路验收后，单独立项。

## 历史接口证据

旧包可见 GET/POST/DELETE /person、PUT /person/card、POST /person/batch、GET /person/export/{parkId}、GET /person/query/by-num/{personNum}。这些路径不是新接口合同，尤其不能沿用把人员或凭据边界完全交给前端的做法。

## 验收

覆盖工号查询、6 位格式、编辑后重新下发确认、导入前缺园区、模板下载、行失败清单、园区越权、导出审计和敏感字段脱敏。旧指纹占位必须在新页面中明确标记不可用或移除，不能以空按钮造成误导。
