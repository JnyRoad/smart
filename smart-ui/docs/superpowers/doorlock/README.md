# 门锁 Web 后台复刻规划

状态：旧页面操作对版参考；当前实现基线为 [011 门锁统一规格](../../../../specs/011-doorlock-oracle/spec.md)、[Web/H5 契约](../../../../specs/011-doorlock-oracle/contracts/web-h5.md) 和 [任务清单](../../../../specs/011-doorlock-oracle/tasks.md)。本轮修订设计，不表示页面或后端已实现。

本目录的页面字段、按钮、弹窗与对版清单继续使用；与新规格冲突的独立服务直连、凭据迁移、指纹能力、任务状态和旧切换假设以 [设计修订记录](../../../../specs/011-doorlock-oracle/design-revisions.md) 为准。历史 implementation-plan 不再单独驱动开发。

## 目标

第一版在 Smart 的管理后台中复刻旧门锁系统 smart-ui 的管理操作。这里的“一摸一样”指管理员完成业务时看到的入口、筛选条件、字段、按钮、弹窗、确认、校验、禁用、列表、详情页签、导出和结果反馈保持可逐项对照；不以重新设计的工作台替代旧页面。

复刻的是用户操作契约，不是旧接口、旧缺陷或不安全的数据展示：

- 新页面统一调用 Smart 网关下的平台门锁业务 API，平台负责业务关联和园区范围，内部调用 smart-lock；请求集中封装在 smart-ui/src/api/lock/，禁止页面直连旧门锁服务或协议桥。
- 密码明文、完整卡号、指纹模板、网关密钥、原始 TCP 报文和旧系统的硬编码身份参数不复刻。
- 旧页面已知的未完成“指纹采集”占位不应被当作可上线能力；设备或协议未验证的功能保持不可用且说明原因。

## 第一版硬约束

1. 不新建与旧后台并列的“命令中心”或“迁移大屏”来替换旧管理员日常入口；这些运维信息可作为详情、任务结果或后续迭代能力，不能挤掉旧操作。
2. 不直接覆盖当前 smart-ui 中的宿舍门锁页面。先以旧页面清单逐项补齐并完成对版，再决定重复入口的合并、下线或重定向。
3. 所有危险操作仍应保留旧版的显式确认与禁用语义；新后端返回“已受理/待设备确认”时，页面不得展示为物理操作已完成。
4. 旧 Web 菜单是登录后动态获取的。旧部署的真实菜单名、层级、URL 和资源码尚未从运行态取得，属于 OPEN-008 的证据项。
