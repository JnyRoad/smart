# 裕慧家园统一客户端

`smart-app/` 是裕慧家园的新客户端骨架，采用 uni-app x、Vue 3 和 UTS，面向 Android、iOS、Web、微信小程序和支付宝小程序复用同一套业务核心。它承接首期两项业务：保密物品放行、供应商进出保密区；物品放行提供申请、审批、现场执行和记录；供应商仅扫描既有厂牌、核验资格、登记进入或离开并查询通行记录，资格在入厂申请时办理。

当前项目已完成首版 App 专用接口及隔离本机闭环：认证服务签发 App 会话，平台服务读取可信身份，并提供物品放行和供应商厂牌的独立业务接口。本机 Docker 已启动网关、认证、UPMS、平台、Nacos、Redis 和 Oracle，自动验证三类人员登录、物品申请至双岗完成、厂牌进出和失败路径。它们均为新增、版本化路径且默认关闭，既有 OA、H5、后台和 OAuth 入口不变。本机的 DHR 适配器、人员和访客均为虚构数据；真实 DHR、真实人员和现场设备仍须单独验收，不能把演示结果当作生产能力。

## 登录、身份和权限

登录表单统一接收工号和密码，身份类型由服务端返回。正式员工及外包／派遣工作人员都映射到同一套 `Identity` 契约，至少包含稳定的 `subjectId`、工号、姓名、人员来源、所属单位、权限码和授权岗位。供应商人员不登录 App，继续通过 H5 入厂申请办理资格；他们与使用 App 的外包／派遣工作人员是不同业务角色。系统内外包／派遣人员由系统凭据校验；DHR 同步的正式员工通过后端可替换的 DHR 凭据适配器校验。本机 profile 使用虚构 DHR 适配器；接入真实 DHR 时只替换适配器配置与实现，不改变 App 协议或页面逻辑。

真实登录分两步：统一网关的 `POST /api/v1/sessions` 只签发 token，`GET /api/v1/me` 根据 token 和当前人员主数据返回身份、权限和岗位。密码只在 HTTPS 请求正文，token 仅在内存；`runtimeConfig.apiBaseUrl` 默认为空，空地址不会发送请求。启用配置、路由前缀和真实接口契约见 [集成说明](docs/integration.md)。

演示入口必须由用户显式进入，使用进程内的正式员工、外包、派遣、主管和安检虚构身份，数据不会写入真实服务。退出、账号切换或会话过期会清空身份、权限、岗位和页面业务状态；本地只允许保存设备扫码偏好和按身份隔离的常用入口。扫码方式只在“我的 → 设置”选择并明确保存，业务页面直接使用已保存方式；退出与重启后继续生效，清除应用数据后需重新设置。

## 扫码和现场核验

PDA 的实体扫码头按键扫描后作为键盘输入写入当前编辑框，硬件模式收到回车自动处理，不显示确认按钮；申请的已扫封条在输入框上方按扫描顺序追加到末尾并自动显示末尾，使用随编号长度排列的椭圆标签，一行可多个，空间不足自动换行，每枚可点叉号删除，成功或异常后重建输入并恢复焦点。统一解析会去除末尾 CR/LF、保留前导零、拒绝控制字符和超长输入，也不会把扫码内容当作 URL 执行。

申请单从独立的申请选项接口取得可填写的起终点，候选加载失败时保留草稿并提供重试；候选点位不会写入本人安检授权岗位。普通申请人可以没有任何执行岗位。

物品现场执行打开后加载当前岗位可办理单据，搜索框按输入即时筛选单号、申请人、标题和封条，无需回车，也不按字符请求后端。扫码头模式默认聚焦搜索框，完整回车后保留并选中当前码，下一次扫描可直接替换；摄像头模式在搜索框右侧显示扫码按钮，结果填入同一框，不直接跳转或放行。未选择岗位时搜索与相机都禁用，岗位仅在设置修改。

手机和没有实体扫码头的 PDA 可在“我的 → 设置”选择相机模式并保存；App 和微信通过 `uni.scanCode` 接入相机调用；Web 与支付宝相机暂未适配，页面会给出明确提示。上述相机调用尚未进行真机验收。物品放行时，安检操作人由 token 和当前员工主数据确认；选择押运人时，将 PDA 或相机读取的工牌号交由后端按当前员工主数据核验，选择定位锁时录入锁号。首版不把普通文本输入当作读卡器加密证明，正式读卡设备接入时可替换后端卡证适配器。

## 本地命令

在 `smart-app/` 目录运行。测试依赖 Node 24 以上，本轮使用 Node 24/26 验证；HBuilderX 原生编译使用安装目录内的 Node 22，不要用 Node 18 编译 Vapor。

```bash
npm test
npm run build:web
npm run build:weixin
npm run build:alipay
npm run build:android       # 仅编译 Android 原生源码，不生成签名 APK
npm run preview             # 默认监听 127.0.0.1:5179
npm run test:e2e            # 需要先运行 npm run preview，并准备 Playwright

# 已启动 docker/app-demo 后，临时接入本机网关并在完成后恢复默认安全配置
npm run demo:enable
npm run test:demo-api
npm run demo:disable
```

`npm test` 通过 `scripts/uts-loader.mjs` 将无平台依赖的 UTS 核心模块加载到 Node 测试运行器。HBuilderX 5.24 已验证 `.uvue` 的 `lang="uts"` 脚本可以导入普通 `.ts`；因此纯业务算法可以使用可擦除 TypeScript 语法，平台 API 和跨端入口仍应遵循 UTS/uni-app x 边界。当前仓库的共享核心统一使用 `.uts`，Node 加载器也只为 `.uts` 注册钩子；新增 `.ts` 测试模块前应把同一套 `stripTypeScriptTypes` 钩子扩展到 `.ts`，避免把 Node 专用 API 带入核心。

E2E 所需依赖可以临时安装，不要把浏览器缓存或凭据提交到仓库：

```bash
npm install --no-save playwright
npx playwright install chromium
```

如果依赖需要放在仓库外，设置 `PLAYWRIGHT_MODULE_PATH` 指向包含 `playwright` 的外部 Node 模块目录。E2E 只覆盖演示数据；浏览器演示通过不等于真实后端、微信、设备或生产验收。

## 厂牌通行与体验修订
供应商不在 App 内申请审批。安检先在设置中确认授权岗位，再进入“厂牌扫码核验”，扫码后查看姓名、照片、公司、人员与被访人联系方式、授权区域、期限与当前状态，明确选择登记进入或离开。每次登记生成独立事件，通行记录按进入/离开及人员、单位、厂牌搜索。演示东门有效厂牌为 `DEMO-BADGE-001`，另有 `DEMO-BADGE-EXPIRED`、`DEMO-BADGE-DENIED`；演示只认预置凭证。

外包与派遣在界面统一显示为“外包／派遣人员”，身份契约仍保留来源值；身份类型不决定审批或执行权限。底部导航统一图标，审批同意/驳回并排并留出间距，公共按钮、输入、列表及空态使用统一触控尺寸和留白。当前验收进度以 [验证记录](docs/validation.md) 为准。

## 设备设置与现场岗位
扫码方式在“我的 → 设置”选择并显式保存，使用 uni.setStorageSync 的设备持久存储；不需要新数据库。所有扫码页响应式读取已保存配置，不再提供临时切换按钮；存储失败保持原配置并明确报错。该设备偏好在换人登录和重启后继续有效，不保存密码或权限。

工作台及“我的”移除岗位选择。岗位只在设置中编辑并保存；物品现场执行列表、扫码定位、执行详情和供应商厂牌核验顶部只读显示当前岗位。旧选岗链接跳转设置，设置岗位项和状态写入均要求 item-pass:execute 或 supplier:execute。未选岗的执行列表、查询、扫码和执行直链均不能办理，普通申请字段不受影响。人员来源不授予或阻止安检角色。普通申请人只在申请表内填写单据出发/到达字段。执行岗位只在当前会话保留，换人登录后清空，操作界面始终提示核对岗位与设备位置。

## 连续扫码与押运方式
封条结果位于输入控件上方，按扫描顺序追加到末尾并自动显示末尾，以椭圆标签按编号长度横向排列并自动换行，可点叉号删除；列表随内容增长，限制最大高度并可滚动。硬件扫码接收回车后自动添加和回焦，删除后同样可以直接继续扫码。
物品出发执行必须选择押运人或定位锁；押运人需刷卡并由后端复核工牌对应的当前员工，定位锁需填写编号并保留前导零。到达沿用出发方式重新核验，定位锁必须同号。真实请求只走 App 专用接口；办理完成后详情显示本次结果，单据同时从当前岗位待办移出。设备输入与相机扫码仍需真机验收。
