# 访客入厂申请作废

## 目标与范围

访客在“申请详情”中可以作废本人名下的任一非作废入厂申请。作废后，申请单在园区系统内立即失效，访客可发起新的重叠时段申请。

本功能覆盖待审批、已通过、已到达、已拒绝、已过期、已离开及权限下发中/失败的历史申请；已作废申请不重复展示操作。

## 业务规则

1. 作废身份校验必须使用现有 `X-Visitor-Query-Token`，并且申请单手机号必须与凭证手机号一致；不能仅凭申请单 ID 操作。
2. 作废是终态：申请状态新增 `7=已作废`，且不允许再由 OA 回调改回已通过或已拒绝。
3. 待审批且存在 OA 流程号的单据，在本地作废后请求撤销 OA 流程；OA 撤销调用失败不回滚本地作废，服务端记录告警，避免单据恢复有效。
4. 对已经提交或成功下发的人员、车辆权限，作废时必须取消未执行的下发任务，并创建或复用删除任务回收已下发权限。
5. 设备删除任务为异步执行：页面成功表示单据已失效且回收任务已提交，不表示所有现场设备已完成回收。
6. 重复申请校验必须排除“已拒绝”和“已作废”申请，其他既有拦截语义不变。

## H5 交互

- 非“已作废”的详情页显示“作废申请”。
- 点击后必须二次确认：`确认作废该申请？作废后单据立即失效，已下发的通行权限将进入回收流程，且不可恢复。`
- 确认期间按钮禁用并展示“作废中…”。成功后刷新详情，展示“申请已作废”，并提供“再次预约”。
- 操作失败保留当前详情和错误提示，不跳转、不清空查询凭证。

## 接口契约

`POST /platform/admittance/apply/app/revoke`

请求头：`X-Visitor-Query-Token: <token>`

请求体：

```json
{ "applyId": "123456" }
```

成功响应沿用统一 `Result<Boolean>`，`data=true` 表示本地作废和权限回收任务提交成功。

## Web 管理端接口与权限

- 管理端使用 `POST /platform/manage/admittance/apply/revoke`，body 为 `{ "id": 申请单ID }`。
- 该路由刻意不使用 `/platform/admittance/**`：后者是访客 H5 的历史放行路径。
- 按钮及接口统一要求权限码 `platform_visitor_incoming_revoke`；上线前须在菜单管理中创建“作废申请”按钮权限，并授予需要操作的角色。

## 验收场景

1. 本人可作废待审批单，OA 回调随后到达时不会再下发权限。
2. 本人可作废已通过且已下发权限的单，人员与车辆删除任务均被提交。
3. 其他手机号、非法 ID、已作废单不得执行操作。
4. 作废单不再触发重复申请拦截，访客可重新申请同一时段。
5. H5 仅在确认后调用接口；成功后显示已作废和再次预约入口。
