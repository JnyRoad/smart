# H5 遗留参考与一期范围

## 已确认的一期范围

用户要求第一版复刻旧门锁系统 smart-ui 的后台页面操作。该要求直接适用于管理 Web，详细清单见 smart-ui 的 WEB-L-001 至 WEB-L-008；H5 不自动复制旧 H5 的所有页面。

一期 H5 保留并完善当前 smart-h5 的员工本人宿舍流程：

- 从 /dorm 进入本人门锁；
- 在 /dorm/lock 查看本人动态密码/门锁状态，修改本人受控密码；
- 在 /dorm/get-code 进行人脸校验并刷新动态码；
- 在入住详情等既有入口保持同一份本人门锁查询缓存和结果语义。

## 旧 H5 仅作参考

旧包中可见 /key/myKey 与 /key/record：

| 旧入口 | 旧行为 | 一期处理 |
|---|---|---|
| /key/myKey | 展示个人密码、IC 卡、指纹状态、已授权设备并提供远程开门。 | 不自动复制；其中远程开门及凭据展示需另行评估设备能力、安全和业务必要性。 |
| /key/record | 当前用户开门记录列表与底部切换。 | 不自动复制；若员工需要查看本人记录，应以最小化字段、分页和服务端本人身份为前提另立需求。 |

旧 H5 远程开门请求中出现硬编码人员标识。这是已知不安全缺陷，严禁复刻；任何 H5 请求都必须由服务端从登录态判定本人、租户和数据范围。

## OPEN-H5-001：遗留 H5 功能是否纳入

待业务确认：是否在后续迭代将“本人开门记录”或“本人远程开门”纳入 smart-h5。该待决项不影响当前 Web 后台复刻，但没有确认前不得自行添加这两个入口，也不得用旧 bundle 的接口或参数实现。

## 不可越过的边界

1. H5 不出现人员/凭据管理、授权/撤权、设备/网关/型号管理、告警设置、通信日志、迁移或切换控制。
2. 不接受 URL、localStorage、页面状态传入的可替换人员 ID、设备 ID 来扩大可见范围。
3. 密码、动态码、卡号、指纹状态和人脸流程按最小展示、短时内存、服务端权限与审计处理；不得转存旧凭据。
