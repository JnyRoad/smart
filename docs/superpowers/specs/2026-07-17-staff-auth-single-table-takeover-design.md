# 员工权限单表重新下发设计

## 1. 目标

员工权限重新下发时，历史失败、离线或尚未提交的设备任务不能继续与新任务并行执行；管理员应仍按现有页面和操作流程重新下发。系统只使用既有 `SMT_ISC_DEVICE_TASK` 记录任务与状态，不新增批次表、人员明细表、异步受理接口或新的调度任务。

## 2. 范围

覆盖员工通关权限的既有入口：

- 人员信息页的追加、覆盖和重新下发；
- 人员权限服务内部更新；
- 权限组、组织关系变更触发的员工权限变更。

不改动访客、车辆、入厂申请、临时通行和其他非员工业务。

## 3. 保持不变的行为

- 页面、既有 URL、HTTP `200` 返回和原有进度查询保持不变。
- 新任务仍由当前 `SmtDeviceTaskService` 创建，仍由现有 ISC 调度器执行。
- 不调用 ISC 任务取消接口。
- `SMT_ISC_DEVICE_TASK` 是唯一任务事实表；历史任务不再因员工重新下发而物理删除。

## 4. 单表接管规则

### 4.1 任务识别范围

只处理同一员工的 ISC 卡权限任务，限定条件沿用现有员工权限清理范围：

- `CARD_NO` 等于员工 ID；
- `DEVICE_TYPE` 为卡权限设备；
- `SERVICE_TYPE` 为员工导入或员工人脸更新对应的既有员工服务类型。

不以 `SOURCE_TYPE`、`SOURCE_ID`、`SOURCE_DETAIL_ID`、`INTENT_KEY` 或新批次字段作为判断条件。

### 4.2 创建新任务前的本地状态更新

每次员工权限重下发、追加、覆盖或差量变更，在创建新任务之前执行一条本地更新：

| 旧状态 | 处理 |
| --- | --- |
| 初始化 `0` | 更新为已取消 `4` |
| 失败 `2` | 更新为已取消 `4` |
| 设备离线 `6` | 更新为已取消 `4` |
| 处理中 `3` | 保持不变 |
| 成功 `1` | 保持不变 |
| 已取消 `4`、已过期 `5` | 保持不变 |

更新同时写入固定中文备注“已被重新下发权限替代”和更新时间。该更新与当前业务权限数据更新、新任务创建置于同一业务事务中；任一步失败，全部回滚。

处理中任务不取消、不删除、也不调用 ISC。随后创建的新任务按现有 ISC 流程下发；ISC 接收到新权限后按其既有覆盖行为生效。

### 4.3 调度行为

现有 ISC 调度只选择可执行状态的任务，`STATUS=4` 的任务不会被再次提交。因此本方案不新增调度器、开关、Feign 调用或任务表。

## 5. PR #143 回退范围

移除 PR #143 引入的保密权限申请专用异步批次能力：

- 后端的安全申请 `202 Accepted`、批次受理、内部 Feign 处理、专用定时任务和批次状态聚合；
- 前端安全申请的批次轮询、202 特殊处理和重复提交禁用逻辑；
- `SMT_ISC_DEVICE_TASK` 的来源/意图键围栏查询与专用 Mapper 方法；
- 仅服务该能力的 DTO、VO、测试、文档与配置。

保留安全申请原有的业务审批和原有下发方式；回退不影响员工单表接管规则。

## 6. 数据库恢复

PR #143 的现有回滚脚本作为数据库恢复基础。它删除：

- `SMT_ISC_DEVICE_TASK.SOURCE_TYPE`、`SOURCE_ID`、`SOURCE_DETAIL_ID`、`INTENT_KEY`；
- `SMT_SECURITY_AUTH_APPLY.CURRENT_DISPATCH_BATCH_ID`；
- `SMT_SECURITY_TASK_DETAILS.DISPATCH_BATCH_ID`；
- `IDX_SEC_AUTH_DETAIL_BATCH`、`IDX_ISC_TASK_SECURITY_BATCH`、`IDX_ISC_TASK_SECURITY_INTENT`。

`SMT_ISC_DEVICE_TASK.BATCH_ID` 不属于 PR #143 新增字段，且可能被其他历史业务使用，本次不删除。

执行删列前必须以只读 SQL 确认：四个 ISC 来源字段均不存在非空数据，两个安全申请批次字段均不存在非空数据，并且没有仍处于初始化、处理中或离线状态的安全申请专用任务。任一检查不通过则停止删列，先完成或人工确认现有任务，再重新核查。

## 7. 验收

1. 员工权限重新下发前，旧的初始化、失败、离线 ISC 员工任务变为已取消且保留记录。
2. 旧处理中任务保留，系统不向 ISC 发送取消请求；新任务按原流程创建。
3. 人员信息、内部人员权限、权限组/组织关系入口使用同一取消方法。
4. 访客、车辆、入厂申请任务状态不受影响。
5. PR #143 专用接口、配置、Feign 和前端轮询均不存在；编译、单元测试和原有员工权限回归测试通过。
6. 数据库恢复 SQL 只在全部前置核查通过后执行，并可通过数据字典确认字段和索引已恢复到 PR #143 前状态。
