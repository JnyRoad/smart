# Git 与 worktree

由 [根规则](../../AGENTS.md) 按任务加载。适用于所有文件修改，以及 worktree、分支、提交、推送和 PR 操作。

## 首次写入前

开发包括需求规格、计划、配置、文档、代码和测试。先只读核对当前目录、Git 状态、当前分支、worktree 清单及任务归属，再决定复用或创建；检查完成前不得写开发文件。

```bash
git rev-parse --show-toplevel
git status --short
git branch --show-current
git worktree list --porcelain
```

通过 worktree 清单识别共享主 checkout 与 linked worktree；目录名称相似或已经存在功能分支，都不能单独证明属于本任务。核对本轮上下文、规格和已有任务记录，保护未提交内容。

| 当前状态 | 必须采取的动作 |
| --- | --- |
| `main` 或共享主 checkout（包括功能分支） | 只读确认起点后，先创建本任务独立 linked worktree 和非 `main` 任务分支，再进入该目录写入 |
| 已在本任务 linked worktree，且使用本任务非 `main` 分支 | 直接复用，不另建 worktree 或分支 |
| 已在本任务 linked worktree，但为 detached HEAD | 从当前 HEAD 建立本任务分支，继续使用该 worktree，不重建目录 |
| 位于旧任务或其他任务的 worktree | 保留原状态，创建本任务 worktree；不得混用或擅自接管 |
| 目标分支被其他 worktree 占用 | 核实那个 worktree 是否属于本任务；属于则复用，否则使用不冲突的任务分支，不强制双重检出 |
| 创建或切换失败 | 查明原因并停止依赖写入，不回退到 `main` 或共享目录开发 |

创建 worktree 和任务分支是执行已授权开发所需的隔离步骤；沿用用户明确指定的起点，否则先只读确认合适基线。不要为创建新目录自动 stash、reset、clean、删除旧 worktree、改写分支或覆盖任何他人改动。目录位于仓库内时，先用 `git check-ignore` 确认 worktree 目录被忽略；无法满足隔离要求时停止并说明原因。

任务目录隔离不等于资源隔离。启动应用、容器、测试或数据库前，另行核对端口、Compose 项目名、数据库、测试数据、文件挂载及外部服务，避免不同 worktree 影响同一资源。

## 分支与授权

- 所有修改在任务功能分支完成，经 PR 合并 `main`；禁止直推 `main`。
- 修改文件不自动授权提交、推送、创建 PR、合并或部署；按会话中已明确的授权执行，授权已覆盖的动作无需再次询问。不能从“推送并建 PR”推断“自动合并”。
- 提交前查看当前状态与完整差异，只选择本任务文件，排除依赖、构建产物、测试报告、本机配置、环境文件、密钥、日志、证书和数据库快照。不得提交其他任务的删除或未提交改动。
- 推送前核实目标 remote、分支和待推送提交；PR 描述以最终行为、范围及真实验证结果为准。本地检查不等于远端 CI、设备或生产验收通过。
- 合并、部署、删除分支和删除 worktree 分别核实具体目标与授权；任务完成不自动删除设计与验收资料。
