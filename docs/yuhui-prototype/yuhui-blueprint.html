新增功能开发蓝图

需求方：刘文超　·　开发方：李世勋　·　基线：需求分析 v40 项 + 实施方案 v1.5 + UI 设计画布 v4　·　2026-08-30

本蓝图把 40 项需求整理成「用户需求 → 功能说明 → 界面 → 流程 → 实现方式 → 开发步骤」的完整闭环，供需求方逐项确认。左侧导航切换章节；第 4 章有两个完整可操作原型（App 全流程 Mock + 复刻现有风格的 Web 后台 Mock），可以像真系统一样点。
40需求项（7 大模块，含 8-30 补充的封条扫码与权限清空改造）
23UI 设计稿（App 13 屏 + Web 后台 10 屏，已按最终阶段设计）
7开发批次（批次 0 缺陷修复 → 批次 6 远期），依赖关系已排定
2剩余开放项：生产任务开关核查、打印机与 PDA 机型采购

这次要解决什么问题

  1. 厂牌打印全面模板化——现在访客凭条版式写死在代码里，改一个字都要发版。做一个可视化模板设计器，外包工 IC 卡厂牌、访客厂牌（保密带二维码）、免检证全部用模板打印，做完一次性切换。
  2. 保密物品放行搬上 PDA——新建「裕慧家园」App（公司唯一移动端，按权限展示模块）：物料贴封条、扫封条直接带出单据、A点出发确认 → 押运（刷卡或定位器锁）→ B点到达归档，全程刷卡验证、全程留痕可查。
  3. 访客管理补短板——申请判重按新厂/老厂分开、随行人员也判重、一键作废回收权限、搜索体验修复、访客手动下发权限带有效期。
  4. 保密权限管住生命周期——考试不通过不给保密权限；供应商协议到期自动收权限；长期未进保密区自动删权限（先演练后启用）；删除权限改成「设备确认删除成功后才清系统记录」，杜绝系统删了、门禁机还能刷的漏洞。

怎么确认这份蓝图

建议按顺序看：核心流程图（第 3 章，业务全貌）→ 交互原型（第 4 章打开 App/Web 原型，按剧本把一张单据从申请点到归档）→ 逐个功能模块（确认功能描述与界面是否符合预期）→ 开发批次（确认先后顺序）→ 最后在确认清单（第 8 章）逐项打勾回复。配套材料：全套 UI 设计稿（可在线圈批）。

决策结论理由
