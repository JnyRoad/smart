# 员工隐私接口分层与 Nacos 精确收口设计

**状态：已批准，待实施计划审核**  
**适用分支：** `fix/staff-pii-access-control`  
**生产配置范围：** Nacos `yuto_prod / dev`  
**不在范围内：** `smart-h5-vue2`（已下线，不修改、不回归、不发布）

## 1. 背景与已验证事实

外网可通过工号访问 Platform 的员工查询接口，并获取完整员工对象。`SmtStaffController` 的 `/simple/badge`、`/define/badge` 和 `/simple/get/badge` 直接返回员工实体；当前 Smart H5 的入住资料模型可接收证件号、住址等敏感字段。

只读核查确认，生产实际使用 Nacos `yuto_prod / dev`。其中 `smart-platform.yml` 将 `/staff/**`、`/articlesrelease/**` 等加入 `security.oauth2.client.ignore-urls`；UPMS 存在 `/api/**`；data、algorithm、push、dispatcher 和多个 bridge 服务存在 `/**`。这些配置使资源服务的 `permitAll` 覆盖业务接口。

仓内已确认的调用方包括 Smart UI、当前 Smart H5、smart-app 后端、smart-upms，以及 Platform 内部服务。仓外调用方必须在生产收口前通过网关访问日志和业务负责人确认。

## 2. 目标与不可变约束

### 2.1 目标

1. 任何外网匿名请求均不能读取员工个人信息或门锁动态码。
2. 外部接口遵循最小字段返回；不得将 `SmtStaff`、`SmtStaffDTO` 或数据库实体直接序列化为 HTTP 响应。
3. 当前 Smart UI、Smart H5、Smart App、UPMS 和内部服务调用保持可用。
4. Nacos 仅保留经确认的精确匿名路径；禁止业务通配放行。
5. 每一批变更均可独立验证和回滚，回滚不恢复通配匿名入口。

### 2.2 不可变约束

- 生产 Nacos 不由本分支自动写入；只提交不含秘密的差异清单、发布模板和验收记录模板。
- 旧 Vue2 H5 不得被修改或作为发布依赖。
- 任何响应、日志、测试 fixture、文档和告警不得保存真实身份证号、手机号、证件照片、人脸信息或生产凭据。
- 不以 IP 白名单、`from` 请求头或前端隐藏字段作为唯一授权机制。
- 不直接删除现有匿名规则；必须在新接口、调用方迁移和灰度验证完成后收口。

## 3. 方案选择

### 3.1 被拒绝方案

- **仅删除 Nacos 白名单：** 会先于调用方迁移造成 Smart UI、当前 H5、App 或 Feign 中断。
- **仅给旧接口加登录校验：** 可阻止匿名访问，但不能阻止已登录用户按任意工号读取他人信息，也无法消除过度返回。

### 3.2 采用方案：接口分层、稳态迁移、Nacos 精确收口

将 API 按外部用户接口、内部服务接口和回调接口分层；先新增最小字段契约并迁移所有调用方，再逐服务从 Nacos 删除通配规则。外部接口认证、授权和字段最小化三者同时成立；内部接口使用服务身份、内部标识、网关拒绝和网络隔离四层保护。

## 4. 目标架构

```text
Smart UI / 当前 Smart H5 / App 客户端
             │ OAuth 用户令牌
             ▼
外部 Gateway ──► 外部业务 API（认证 + 权限/归属 + 最小 DTO）
             │ 禁止 /internal/**
             ▼
        Platform 业务服务
             ▲ OAuth 服务令牌 + 内部标识
             │
Smart App / UPMS / 其他内部服务 ──► /internal/...（用途 DTO）

外部回调 ──► 精确路径（签名校验、时间窗、重放防护）
```

### 4.1 外部 API

| 场景 | 新接口语义 | 返回字段 | 授权规则 |
|---|---|---|---|
| Smart UI 人员搜索 | `GET /staff/lookup` | `staffId`、`badge`、`name`、`departmentName` | 已登录且拥有人员查询权限 |
| Smart UI 人员详情 | `GET /staff/admin/{staffId}` | 基础资料与按权限脱敏字段 | 已登录、角色权限、园区数据权限、审计 |
| 当前 H5 入住 | `GET /staff/me/check-in-profile` | `name`、`profileComplete`、必要的脱敏展示字段 | 仅当前登录员工；无 `badge` 参数 |
| 当前 H5 门锁 | `GET /dormitory/me/lock-code` | 仅本次使用的受保护门锁数据 | 员工本人或被授权宿舍管理员；校验园区、房间和在住关系 |
| 当前 H5 物品放行 | 受控人员选择接口 | `staffId`、`name` | 当前用户与放行单、园区和审批状态匹配 |

入住和门锁提交时，服务端从认证主体读取员工身份；不得信任客户端提交的工号、身份证号、房间归属或人员 ID。前端不再用“输入工号后回填完整档案”的方式组织业务。

### 4.2 内部 API

内部服务接口位于 `/internal/staff/...`，按用途拆分 DTO。每一个内部消费者都要先记录所需字段、业务目的和数据责任人；接口只暴露该目的所需字段，禁止创建“内部全量员工资料”通用接口。

内部请求必须同时满足：

1. OAuth `client_credentials` 服务令牌及最小 scope；
2. 明确的 `FROM_IN` 内部标识和 `@Inner` 检查；
3. Gateway 拒绝 `/internal/**` 的外部路由；
4. 网络层仅允许集群内部服务网段或 Service 访问业务端口。

`FROM_IN` 仅作为调用语义校验，不能单独证明身份。`security.inner.mode` 先保持 `AUDIT`，在所有 Platform `@Inner` 端点及异步调用审计完成后才按服务开启 `ENFORCE`。

### 4.3 响应、日志与审计规则

- Controller 返回明确 DTO；服务实体只允许在服务层和持久层使用。
- 身份证、手机、住址、邮箱、微信号、证件照片、人脸资料默认不返回。经书面业务授权的后台详情仅允许脱敏展示；明文查看必须独立权限和审计。
- 审计日志记录接口、调用主体、园区、结果、关联业务单号和脱敏后的查询标识；不记录敏感值。
- 对按工号、手机号、人员 ID 的枚举请求增加速率限制和异常访问告警。

## 5. 调用方迁移边界

| 模块 | 必须迁移的流程 | 保持不变的用户体验 |
|---|---|---|
| `smart-ui` | 人员搜索、人员详情及其复用页面 | 下拉搜索、选择员工、正常提交 |
| `smart-h5` | 入住、门锁、物品放行 | 用户自己的入住、门锁和放行业务流程 |
| `smart-app` | 登录绑定、密码、挂失、资料完善及银行相关员工查询 | App 既有业务完成条件 |
| `smart-upms` | 用户初始化时的员工查询 | 登录和权限初始化 |
| `smart-platform` | 内部服务、Wrapper、审批和访客相关查询 | 现有业务规则；仅替换数据契约 |
| data、algorithm、push、dispatcher、bridge | 所有被 `/**` 覆盖的 Controller | 已确认的内部任务和签名回调 |

## 6. Nacos 精确收口规则

### 6.1 允许进入 `ignore-urls` 的条件

只有同时满足以下条件的精确路径才允许匿名：无个人信息、无状态变更风险，或已具备独立签名校验、时间窗和重放防护的第三方回调。健康检查和 API 文档与业务路径分开处理。

### 6.2 必须移除的模式

- Platform：`/staff/**`、`/articlesrelease/**` 及任何以业务前缀替代授权判断的通配路径。
- UPMS：`/api/**`，改为 App 身份、scope 和园区授权。
- data、algorithm、push、dispatcher、bridge：`/**`，改为精确内部路径或签名回调路径。
- 所有服务：任何新出现的 `/staff/**`、`/api/**`、`/**` 必须在 CI 配置检查中失败。

### 6.3 发布产物

本分支提交以下不含秘密的材料：Data ID 清单、删除和新增路径差异、前置调用方、灰度顺序、发布后探针、回滚版本填写栏和负责人签字栏。实际 Nacos 内容、账号和生产密钥不进入 Git。

## 7. 发布与回滚设计

1. 发布新 DTO、内部服务令牌能力、授权校验和可观测性，但保留旧路径。
2. 分别迁移 Smart UI、当前 Smart H5、App、UPMS 和 Platform 内部消费者。
3. 在预发和灰度实例完成外部拒绝、内部调用、前端端到端和异步任务验证。
4. 一次仅变更一个服务的一个 Data ID，先灰度后扩大。
5. 旧接口调用量为零并经业务负责人确认后，删除旧 Controller 路由和旧 DTO。

若出现回归，优先回滚当前调用方或当前 Data ID 历史版本；不得以恢复 `/staff/**`、`/api/**` 或 `/**` 作为应急手段。确需临时兼容时，只能恢复到经认证、精确路径和最小字段的前一版本。

## 8. 验收标准

1. 无 Token、伪造 `FROM_IN`、越权工号、跨园区人员 ID 请求均返回 401 或 403，且不含敏感字段。
2. Smart UI 人员搜索与管理流程、当前 H5 入住/门锁/物品放行、App、UPMS、Feign 和定时任务均通过回归。
3. 响应 schema、日志和测试 fixture 中不存在禁止字段。
4. Nacos `yuto_prod/dev` 已无未经批准的业务通配匿名规则。
5. 每个 Data ID 均有变更 diff、灰度记录、验收结果和可用回滚版本。

## 9. 开发前阻塞项

实施前必须完成两项外部确认：

1. 仓外调用方清单：由网关日志和业务负责人确认，特别是设备、脚本和第三方回调。
2. 服务网络隔离能力：由运维确认 Gateway、Ingress、防火墙或 NetworkPolicy 的实际部署边界。

这两项不阻止代码和测试先行，但在删除生产 Nacos 通配规则前是硬性发布门禁。
