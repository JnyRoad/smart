# 研究记录：手动下发权限有效期

## 决策 1：日期语义和默认值

- **决策**：请求字段使用 `startTime` 与 `endTime`；将日期归一为开始日 00:00:00 和截止日 23:59:59。缺省值是服务端当天至 2030-12-31。
- **理由**：管理员按日期授权，不应因时分秒造成当天不可用或截止日过早失效；服务端默认可兼容现有调用方。
- **备选方案**：要求客户端传完整时间并拒绝旧客户端。未采用，因为会破坏现有接口调用。

## 决策 2：时限的执行位置

- **决策**：将时间窗口传给 ISC 下发任务和设备端权限配置，不在本地创建延迟删除任务。
- **理由**：5.3 蓝图明确设备端窗口到期自动失效；本地任务链路已有时间字段可承载该窗口。
- **备选方案**：创建本地延迟删除任务并在到期时回收。未采用，因为超出本期范围且会引入删除回执与重试状态机。

## 决策 3：关系记录的角色

- **决策**：员工—权限组关联存储起止时间，限于展示；下发任务是设备端生效窗口的事实来源。
- **理由**：需要保留管理员当次授权期限，但蓝图明确本期不按此记录驱动本地清理。
- **备选方案**：只写任务不写关联。未采用，因为列表展示将丢失授予期限。

## 决策 4：权限组入口复用

- **决策**：通行权限、门禁通关权限、考勤通关权限继续复用同一人员批量粘贴窗口和 API 请求结构。
- **理由**：它们只由权限组类型区分，日期交互和后端校验必须一致。
- **备选方案**：分别复制三个弹窗。未采用，会造成校验和默认值漂移。

## 决策 5：同设备多权限组的窗口覆盖

- **决策**：同一员工的多个权限组命中同一设备时，任务使用最后一次授权关系的起止日期，直接覆盖此前窗口。
- **理由**：人工操作只需关注本次授权，日期断档不应阻塞下发或要求管理员理解区间合并规则。
- **备选方案**：合并连续区间并拒绝断档。未采用，因为会扩大实际授权区间且容易阻断正常人工操作。
