# 实施方案：保密区权限自动删除记录报表

**分支**：`feat/security-auth-delete-report` | **日期**：2026-09-05 | **规格**：[spec.md](spec.md)

## 概述

采用独立审计主表和任务关联表。主表保留人员、部门、权限组及判定依据快照，关联表记录一次判定生成的全部设备任务；查询聚合设备任务当前状态，避免把生成任务误报为成功。自动删除逐条使用实际生效的事务边界，失败后独立记录。界面沿用 Vue 2 / Element UI 报表样式。

## 技术上下文

- Java 8、Spring Boot 2.1、MyBatis-Plus、Oracle；不增加中间件。
- `smart-platform-core`：实体、Mapper、XML；`smart-platform-api`：请求/响应契约；`smart-platform-biz`：审计写入、查询、权限控制、现有自动任务接入。
- `smart-ui`：服务端筛选、分页、导出、关联任务弹窗、演练配置。
- 验证：JUnit/Mockito 业务测试、MyBatis BoundSql 契约测试、Vitest 组件/API测试、针对改动的 lint 和构建。
- 首页目标 3 秒；真实 Oracle 执行计划和规模压测仍需现场验收，不能从 B-tree 或 Mock 推断性能。

## 模块与接口

1. 自动判定服务：保留既有阈值计算和白名单策略，新增快照、演练、逐条事务与失败持久化；正式删除仍使用既有设备任务创建链路。
2. 审计查询服务：集中数据范围、参数校验、分页与导出；任务详情先校验主记录园区归属。
3. 任务创建接口：以兼容方式增加返回任务 ID 的入口，已有 void 调用不受影响。
4. 关联状态：主表正式提交状态为 PROCESSING；查询按全部关联任务派生 SUCCESS/FAILED/PROCESSING/UNKNOWN，缺失任务永不视为成功。
5. 管理页面：只读列表与详情；导出按钮独立权限；演练配置仅影响判定后的动作。

## 交付顺序

## 已知限制

旧任务无自动删权来源，不回填。原任务记录若清理，关联审计仍存在而执行状态标记未知。本次不实现 5.8 完整确认/补偿链路，也不宣称设备物理删权已确认。既有配置 dryRun 为空按 0 处理，编辑未提供该字段时保留原值。

## 补充核验（实施前已同步契约）

设备任务存在普通/ISC两套表且ID类型不同，因此关联键使用来源+任务ID。离线状态6继续等待，过期5属于异常终态；聚合按真实枚举定义。旧void任务创建方法保留原有兼容行为，新增审计入口严格检验任务创建结果。

## 升级交付方案

PR #189 评审修复沿用本方案：缺失全部时间依据时保存 `SKIPPED_MISSING_TIME`，列表、筛选和导出同步支持；任务详情 null 状态沿用契约，在 UI 显示未知。恢复白名单临时输入字段的响应式默认值，路由测试改为核对实际导出路由；复用既有演练校验及 SQL 结果片段。Oracle 执行计划与索引使用仍列为现场验收，未取得计划前不更换聚合算法。

迁移目录为 `smart-module/database/manual/20260905_security_auth_delete_report/`。提供 `precheck.sql`、`upgrade.sql`、`verify.sql`、`rollback_check.sql`，必要的共享校验由同目录脚本复用。检查连接用户/current schema与显式目标一致；在已有结构兼容时跳过已完成 DDL，拒绝不兼容结构。新结构与既有实体和 XML 对齐；不回填历史任务、不重置 dryRun。候选性能索引保持独立、需执行计划依据，不由升级脚本自动创建。

升级顺序：备份并暂停相关自动任务 → 核对 schema → 执行迁移并验证 → 部署 smart-platform-biz → 部署 smart-ui → 配置菜单/角色 → 在测试园区验收 → 按原调度配置恢复任务。应用回滚保留新表和字段；若存在 dryRun=1，旧版本不支持演练，必须先保持调度停用并处理回退条件，不能直接恢复任务。Oracle DDL 隐式提交，异常后的已建对象不由ROLLBACK撤销；应核查后重跑同一增量迁移或由DBA处理漂移。
