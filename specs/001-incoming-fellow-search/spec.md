# Feature Specification: 入厂申请随行人员搜索

**Feature Branch**: `feat/incoming-fellow-search`

**Created**: 2026-09-02

**Status**: 已实现，待可控数据环境完成页面验收

**Input**: 在入厂申请记录中，使用姓名或证件号搜索随行人员时返回所属主申请单。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 按随行人员姓名定位申请单 (Priority: P1)

园区管理人员在入厂申请记录输入一位随行人员的姓名，定位到其所属主申请单后查看或处理申请。

**Why this priority**: 这是本功能的核心业务价值，避免管理人员只能知道随行人却无法找到申请单。

**Independent Test**: 创建一张主申请单和至少一位姓名不同的随行人员，仅用随行人员姓名查询，确认返回该主申请单。

**Acceptance Scenarios**:

1. **Given** 一张申请单的主申请人姓名不匹配、但某位随行人员姓名匹配，**When** 管理人员按姓名搜索，**Then** 返回该主申请单。
2. **Given** 主申请人姓名匹配，**When** 管理人员按姓名搜索，**Then** 继续返回该主申请单。
3. **Given** 同一申请单有多位匹配或不匹配的随行人员，**When** 管理人员按姓名搜索，**Then** 匹配随行人员不会额外增加该申请单的结果行数。

---

### User Story 2 - 按随行人员证件号定位申请单 (Priority: P1)

园区管理人员持有随行人员证件号时，可以在同一页面找到其所属主申请单。

**Why this priority**: 证件号是现场核验中更可靠的人员标识，必须与姓名搜索一致可用。

**Independent Test**: 创建一张含随行人员证件号的申请单，仅按该证件号搜索，确认返回该主申请单且不重复。

**Acceptance Scenarios**:

1. **Given** 证件号只存在于随行人员记录中，**When** 管理人员按证件号搜索，**Then** 返回对应主申请单。
2. **Given** 证件号只存在于主访客记录中，**When** 管理人员按证件号搜索，**Then** 返回对应主申请单。
3. **Given** 证件号与其他筛选条件组合使用，**When** 管理人员搜索，**Then** 只返回同时满足所有已选条件的主申请单。

### Edge Cases

- 搜索条件为空时，列表保持现有默认查询和分页行为。
- 没有任何主申请人或随行人员匹配时，返回空结果而非错误或无关申请单。
- 没有关联主申请单的随行人员记录不得单独出现在结果中。
- 页面名称应明确提示姓名字段同时支持主申请人和随行人员。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须允许管理人员通过现有姓名筛选项匹配主申请人或任一随行人员。
- **FR-002**: 系统必须允许管理人员通过现有证件号筛选项匹配主访客或任一随行人员。
- **FR-003**: 任意数量的匹配随行人员都不得额外增加同一申请单的结果行数；车辆外连接造成的既有重复不在本功能中改变。
- **FR-004**: 系统必须保留既有的筛选参数、分页、排序、园区数据范围和其他组合筛选语义。
- **FR-005**: 页面必须保留简短的“访客姓名”“访客证件号”筛选文案；支持随行人员的范围由既有查询参数对应的后端行为保证，不新增参数。
- **FR-006**: 本功能不得创建、修改或删除业务数据、数据库索引、统计信息或权限配置。

### Key Entities *(include if feature involves data)*

- **入厂申请单**: 列表中展示和操作的主记录，是搜索结果的唯一单位。
- **随行人员**: 关联到一张入厂申请单的人员，提供姓名和证件号搜索依据。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 对只匹配随行人员姓名或证件号的测试数据，100% 返回其所属主申请单。
- **SC-002**: 对含三位以上随行人员且无多车的同一申请单，任何一次姓名或证件号搜索均只展示一条申请单结果；有多车时，匹配随行人员前后的同一申请单行数保持一致。
- **SC-003**: 主申请人姓名匹配、空搜索和与其他筛选条件组合的既有验收场景保持通过。
- **SC-004**: 本功能上线不包含任何数据库 DML、DDL、索引或统计信息变更。

## Assumptions

- 姓名和证件号保持当前包含式匹配习惯，用户可输入部分关键字。
- 主访客和随行人员的证件号字段均可用于包含式匹配；字段值完整性由既有入厂申请数据治理保证。
- 数据库规模、索引、统计信息和执行计划均会在任何后续数据库变更前重新核验。
- 孤儿随行人员记录属于独立数据治理范围，不在本功能中清理。
