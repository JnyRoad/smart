# Feature Specification: 可靠权限删除与批量调度

**Feature Branch**: `docs/reliable-auth-batch-design`

**Created**: 2026-09-05

**Status**: 已确认需求，实施中

**Input**: 旅途确认实施蓝图 5.8，同时覆盖 ISC 和设备直连；高峰上万条指人员与设备展开后的任务，批量新增、更新、重发、删除均为一期范围。

## User Scenarios & Testing

### User Story 1 - 删除结果可信且失败可恢复 (Priority: P1)

管理员撤销人员权限后，能看到删除进行中、失败设备和重试结果。所有应删除设备确认前保留本地删除依据，设备失败不能表现为已删除。

**Why this priority**: 解决系统已删而设备仍可通行、残留持续累积的问题。

**Independent Test**: 一个主体关联多设备，分别返回成功、失败和未知；仅全部可信确认后完成删除。

**Acceptance Scenarios**:

1. **Given** 员工曾获得多设备权限，**When** 删除时有设备离线，**Then** 在线设备继续处理，授权显示未完成并保存离线目标。
2. **Given** 最后一个目标确认后本地处理异常，**When** 服务恢复，**Then** 可重放结果并完成本地收敛。
3. **Given** 当前权限组已不含历史设备或缺少人脸图片，**When** 撤权，**Then** 仍依据历史身份和目标处理，不能静默跳过。
4. **Given** 任务未创建、被取消或结果缺失，**When** 汇总，**Then** 不能判为删除成功。

### User Story 2 - 万级高峰仍可撤权和查看进度 (Priority: P1)

管理员集中提交一万至两万条设备任务后可以继续使用系统，小批撤权不被大批新增、历史清理或离线重试长期阻塞。

**Independent Test**: 两万新增目标排队时插入小批撤权并持续确认结果，观察各类业务持续推进和可恢复计数。

**Acceptance Scenarios**:

1. **Given** 万级任务集中进入，**When** 系统返回受理结果，**Then** 返回可追踪批次，后台分段处理，重启后续接。
2. **Given** 新增积压、结果待处理和历史清理同时存在，**When** 新撤权进入，**Then** 新增、撤权和结果处理均有保留能力。
3. **Given** 多台设备包含离线设备，**When** 处理批次，**Then** 健康设备继续推进，离线目标延期且不会反复重跑成功目标。

### User Story 3 - 并发授权不会被旧任务破坏 (Priority: P1)

同主体、同设备上先后发生新增、覆盖、删除时，以当前有效授权来源为准；旧回执不能恢复已撤销权限或清理新授权。

**Independent Test**: 两权限组共享设备并发撤权，以及新增/删除乱序回执，最终设备与有效来源一致。

**Acceptance Scenarios**:

1. **Given** 同一授权正在删除或失败待处理，**When** 对同一来源重新下发，**Then** 明确提示冲突。
2. **Given** 另一有效来源仍需通行，**When** 删除当前来源，**Then** 保存保留依据，不能误删共享权限。
3. **Given** 旧删除迟到且影响新授权，**When** 取得执行证据，**Then** 对当前仍有效的设备目标补偿，原结果保留。

### User Story 4 - 查找并治理历史残留 (Priority: P2)

管理员可按园区查看残留和失败目标，重发未完成项或依据实际核验确认清理；历史治理在业务繁忙时让出资源。

**Independent Test**: 构造本地授权已不存在的已知历史目标，对账发现、创建补偿并保留核验轨迹。

### User Story 5 - 两种接入使用一致完成口径 (Priority: P1)

ISC 为首个灰度接入；直连门禁同样保留未确认目标和失败原因。平台受理、平台无条目与设备确认分开展示。

**Independent Test**: 分别使用 ISC 与直连测试适配器验证相同生命周期，再按现场实际型号联调。

### Edge Cases

- 空目标必须有可信无权限或其他有效来源保留依据；空查询不自动完成。
- 同一请求重复提交、跨批次重复操作、租约过期旧执行者、提交成功但响应丢失。
- 设备超过一页、明细分页丢项、重复/迟到回执、权限有效期不同、身份发生变更。
- 任务展开未完成即超时、部分展开后崩溃、失败后旧任务仍在途。
- 不支持查询或执行的设备类型明确显示限制，不得以取消视作成功。

## Requirements

### Functional Requirements

- **FR-001**: 所有撤权入口必须保存可恢复删除意图，在全部预期目标确认之前保留本地依据。
- **FR-002**: 受理、准备、排队、执行、待确认、待核验、失败、完成必须可区分；返回受理不等于设备成功。
- **FR-003**: 批次须支持稳定目标选择、分段展开、幂等重试与崩溃续接，不漏计未展开目标。
- **FR-004**: 大批新增、更新、重发、撤权共享一致批次口径，分别有保留处理能力；对账和重试限额执行。
- **FR-005**: 按接入实例、园区、设备限制速率及在途工作；慢设备不能阻塞其他设备。
- **FR-006**: 批量执行须保留各目标的有效期、身份和结果归属，不因合并扩大授权。
- **FR-007**: 结果证据必须可恢复处理，任务成功与本地收敛之间的异常不能丢失。
- **FR-008**: 仅全部预期目标可信成功才自动完成；平台无条目、超时、取消、空任务均不能替代设备确认。
- **FR-009**: 失败按原因延期重试，仅重发未确认项；超过等待或重试上限后保留失败原因并告警。
- **FR-010**: 同一授权来源删除期间禁止重新下发；共享设备按所有仍有效来源协调。
- **FR-011**: 旧版本任务和重复回执不能改变当前授权，必要时根据当前有效来源补偿。
- **FR-012**: 历史设备、缺人脸、已删除本地关系仍能形成可核验补偿目标；证据不足明确待核验。
- **FR-013**: 管理员能按可见园区分页查看批次/目标、重发未完成项、记录人工核验及操作审计。
- **FR-014**: ISC 与直连分别验证；员工、访客和车辆来源有明确归属，不支持的操作显式失败。
- **FR-015**: 分别记录受理、展开、排队、设备确认和本地收敛时间及各队列最老等待时间。
- **FR-016**: 自动异常扫描和分段对账发现残留，繁忙时停止新增历史清理投递。

### Key Entities

- **操作批次**：一次业务操作、幂等标识、稳定选择范围、展开进度和汇总。
- **删除请求**：一个授权来源的撤权意图、目标版本、期限和结果。
- **设备目标与尝试**：主体及设备资源、预期动作、身份快照、每次执行和可信结果。
- **授权版本**：当前有效来源及并发顺序，不随授权行物理删除而重用。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 分别注入 10,000 和 20,000 个去重设备目标，所有受理请求可追踪、可恢复，零静默丢失、零假成功。
- **SC-002**: 在线、无同目标冲突的小批撤权在两万新增积压中，受理至首次外部提交初始门槛 P95 ≤ 30 秒、最大 ≤ 120 秒；超限须判容量验收失败。
- **SC-003**: 受理初始门槛 P95 ≤ 2 秒、P99 ≤ 5 秒；正常列表 P95 不超过空载基线两倍。
- **SC-004**: 一万人乘十设备的十万目标展开场景中，内存和连接有界，重启不漏目标；不据此承诺终端十万任务完成时限。
- **SC-005**: 离线、限流、丢失/重复/乱序结果及收敛崩溃场景下，健康设备持续推进；未可信确认项始终可见。
- **SC-006**: ISC、直连及混合负载分别出具受控模拟和真实设备结果，记录版本、型号、分布、资源和限流配置。

## Assumptions

- 已确认的蓝图 5.8 是本规格输入，主容量口径为人员设备展开后的任务。
- 复用现有权限、园区隔离与管理界面；一期不引入新消息中间件。
- 60 秒是集中压测注入窗口，不是终端完成期限；容量门槛待实测，不能声称现网已达到。
- 用户已授权本地实施；提交、PR、生产数据库变更及真实设备写入不包含在本轮授权内。
- 缺少实际设备或数据库性能证据时记录未验证，不能关闭对应现场验收任务。
