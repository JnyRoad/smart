# 持久模型与状态契约

本节定义实施契约。物理测试基线位于 `smart-module/smart-platform/smart-platform-core/src/test/resources/auth-operation/operation-schema.sql`，在本任务临时 Oracle 的合成 schema 验证。该基线不代表生产元数据；发布前还须核对目标 Oracle 版本和实际约束。

| 实体 | 关键字段与关系 | 不变式 |
| --- | --- | --- |
| 操作批次 | id、parkId、幂等键、动作/来源、稳定选择集、展开游标、expected/expanded、状态和阶段时间 | 同业务幂等键唯一；选择集冻结；未展开完成不成功 |
| 删除请求 | id、batchId、subjectType、sourceType/sourceRowId、generation、deadline、状态 | 同来源正在删除时不重新授权；孤儿清理保存身份及历史目标替代不存在的来源行 |
| 目标 | id、request/batch、主体/设备资源、接入、动作/有效期、版本、状态、可信结果摘要 | 批内唯一；跨批次由操作幂等键和当前主体设备版本协调 |
| 执行尝试 | id、targetId、transport/taskId、attempt、nextAttemptAt、leaseToken/until、externalBatch/serial、错误 | 领取条件原子；租约过期旧执行者不能写新状态；超时不是未执行 |
| 授权版本 | park/subject/resource、generation、当前有效来源、协调状态 | 版本单调且不因物理删除重用 |
| 结果证据 | attemptId、外部事件键、证据类别、接收时间、收敛状态、失败原因 | 重复幂等；旧结果仍保留；未本地收敛可重放 |

目标状态：PREPARING → QUEUED → EXECUTING → WAITING_CONFIRM → CONFIRMED → CONVERGED；证据不足进入 VERIFYING，可延期重试；耗尽进入 FAILED。平台受理和平台不存在不进入 CONFIRMED。

共享来源保留以 RETAINED 和有效来源证据表示，不伪造设备删除。请求仅在展开数核对一致、全部必删目标 CONVERGED、保留项有依据时成功。终态请求的新证据经接管/补偿处理，不直接改当前授权。

每分片目标/任务关联/游标同事务；批次进度分段汇总可重算。不能每个目标更新同一热点批次行。

已消费分片须保存可精确比较的内容指纹，包含批次、前后游标、来源意图、资源贡献和封口标志。重复游标只允许同内容重放；不能仅因来源请求相同就接受另一组资源或提前封口。分片指纹与该页业务写入、游标推进同事务，存储按页增长，不在每次重放时解析整个批次快照。

工作流分片表 `SMT_AUTH_WORKFLOW_SHARD` 的实施字段为 batchId、previousCursor、nextCursor、shardKind（STAGE/BIND）、contentFingerprint、sourceCoordId、sourceGeneration、createTime。批次前后游标组合主键并对同批次起点唯一，另核批次外键与前后游标顺序；没有整批 CLOB。来源页记录完整规范摘要，绑定页记录明确资源身份，不能混用同一游标。此表正在合成 Oracle 验证，尚不构成生产迁移证据。

## 持久基础的物理契约

| 表 | 必须独立保存的字段 | 约束与用途 |
| --- | --- | --- |
| `SMT_AUTH_OPERATION_BATCH` | 园区、幂等键、动作、来源、选择快照、意图指纹、预期/展开数量、游标、状态、受理/展开结束/首次下发/确认/收敛时间 | `(PARK_ID, IDEMPOTENCY_KEY)` 唯一；同键重试须再比较稳定意图指纹，不同意图明确冲突；未展开完不参与成功判定 |
| `SMT_AUTH_DELETE_REQUEST` | 批次、园区、主体类型、来源类型/行号、稳定来源身份键、身份快照、代次、期限与状态 | 一个批次关联多个请求；批内来源身份和代次唯一；正常来源在应用层校验行号，孤儿补偿允许原行号为空，但身份和历史目标证据必须存在 |
| `SMT_AUTH_OPERATION_TARGET` | 批次/请求/园区、目标键、主体类型/ID/快照、设备ID、资源类型/ID、接入、队列、动作、有效期、操作版本、原任务ID、状态与租约 | 独立设备字段支持设备公平调度；请求必须属于相同批次和园区；批内目标键及业务目标身份唯一，主体类型与接入参与身份，不能把不同类型的相同数字ID合并 |
| `SMT_AUTH_OPERATION_ATTEMPT` | 目标、尝试号、接入、原任务号、外部批次/命令号、令牌/租约、状态、重试时间与错误、结果事件ID | `(TARGET_ID, ATTEMPT_NO)` 唯一；只允许当前令牌写入当前尝试；外部受理不直接变成确认 |
| `SMT_AUTH_RESULT_EVENT` | 目标/尝试、事件键与来源命名空间、接入及外部标识、版本、证据类型、结果、正文、接收/收敛状态 | `(ATTEMPT_ID, EVENT_KEY)` 唯一；同一外部批次事件可分别归属多个目标；尝试与目标通过复合外键核对，旧证据仍可留存 |

批次/园区、请求/批次/园区及尝试/目标使用复合父键和外键约束归属，不能只验证每个 ID 分别存在。申请来源和授权版本还需后续协调服务校验，外键不能代替业务判断。

所有时间按阶段保存：受理时记录批次时间，展开结束记录游标及数量核对时间，目标分别记录下发、确认和收敛时间。批次阶段值可由目标归并计算，普通回执不逐条争抢批次统计行。单条证据正文不保存全批万条人员明细。

新队列元数据时间由统一 UTC 时钟产生并保存，租约和重试比较使用同一时基；不能混用宿主本地时间与容器默认时间。权限有效期 `VALID_FROM/VALID_TO` 保持现有业务语义，由接入适配器按已有接口规范转换。

## 分片、领取与恢复

1. 受理只冻结稳定业务选择与指纹。展开按前置游标条件更新；一个有界分片的请求、目标、原任务关联和新游标同事务，失败可从原游标重试。
2. 对已持久化分片重试时核对目标内容，不能只忽略唯一键错误后推进游标。预期数量与展开数必须相符；零目标进入核验，不能自动成功。
3. 领取按园区、队列、可执行时间和有限数量查询，再用条件更新取得排他令牌；竞争未命中不执行。数据库事务结束后才能发起外部请求。
4. 外部调用前持久标记尝试；响应丢失时保留未知状态。租约过期后，存在外部标识或可能已提交的目标先核验，不能当作未执行直接重发。
5. 回执核对目标、尝试、接入、外部标识和版本后落证据。只有可信设备成功证据允许进入 `CONFIRMED`；本地记录与来源收敛完成后才进入 `CONVERGED`。

领取候选索引为 `(PARK_ID, OPERATION_QUEUE, STATE, NEXT_ATTEMPT_AT, ID)`，批次目标查询按 `(BATCH_ID, STATE, ID)` 索引；实际是否需要调整顺序以有代表性数据及执行计划为准。当前合成 10k 数据命中索引快全扫描与有界排序，不能据此宣称领取查询或万级容量已达标。

## 版本与来源协调契约

上述五表保存操作历史；T013/T014 另保存永久协调状态和历史身份。主体、来源、资源、贡献和别名五表已有本地基础实现；独立审查继续核对补偿恢复约束。业务接入仍未完成，不能据此宣称旧任务已受保护。

| 表 | 身份与必要字段 | 不变式 |
| --- | --- | --- |
| `SMT_AUTH_SUBJECT_COORD` | 园区、主体类型/ID、永久协调键及创建时间 | 同一主体的来源受理与资源证据应用共享短事务锁，避免一方已受理撤权而另一方仍确认旧来源快照；不在该锁内等待设备或展开整批 |
| `SMT_AUTH_SOURCE_COORD` | 园区、业务来源种类、稳定来源键、主体类型/ID、当前来源行号/指纹、永久代次、当前意图/批次、状态及时间 | 同园区/业务来源种类/稳定来源键唯一；来源行删除后保留协调行；删除中或失败待处理时不能重新授权 |
| `SMT_AUTH_RESOURCE_COORD` | 园区、主体类型/ID、接入、设备、资源类型/ID、规范资源键、永久操作代次、已应用代次、精确期望及指纹、阻塞目标/尝试 | 锁定范围是一名主体在一个设备资源上的权限；永久代次原子递增，未知执行只阻塞该资源的后继 |
| `SMT_AUTH_SOURCE_RESOURCE` | 来源/来源代次、资源、原行指纹、精确有效期、贡献状态、请求/目标关联和时间 | 保留历史贡献；在资源短事务内根据当前来源状态重算；多个来源可引用同一物理目标证据，不能重复下发或漏掉来源收敛 |
| `SMT_AUTH_IDENTITY_ALIAS` | 园区、接入、设备/资源、主体、历史卡号或外部人员号/任务号、资源代次和时间 | 接管时保存当前及可证明的历史别名；别名变化不抹除历史；命中多个主体不能自动归属 |

`SOURCE_KIND` 表示业务来源，例如员工权限关系、车辆申请、普通访客、入厂随行人、入厂车辆。普通访客同行人 `VISITOR_FELLOW` 与入厂同行人 `ADMITTANCE_FELLOW` 使用不同主体类型和各自明细 ID；保密区来源仍可指向同一 `STAFF` 主体。现有 batch/request 的 `SOURCE_TYPE` 数值 1–7 表示操作发起原因，保留原含义。请求 `GENERATION` 是来源代次，目标 `OPERATION_VERSION` 是设备资源的操作代次，不能混为一个计数器。

员工权限的稳定来源键为员工 ID 与权限组 ID；物理关系行 ID 仅作当前行快照，不能放入稳定键导致删行重建后避开冲突门禁。申请类来源以不可变业务申请/明细身份区分；不同类型的相同数字 ID 不能合并。所有来源实际表行的更新/删除须再核对行号、业务身份、来源代次及指纹。

同一来源的受理在短事务内冻结意图并改变来源状态，随后分页展开；删除中的来源立即从有效贡献集合排除。来源受理与证据应用按主体协调锁、来源、资源的统一顺序取得锁，资源计算读取一致的来源集合。两个来源同时撤销时，最后一个有效贡献消失会生成实际删除，不能相互保留。不同人员可并行，不能在事务内等待设备响应或锁住整批上万目标。

覆盖更新必须逐资源表达保留/新增与排除：来源整体仍有效，不代表旧设备仍在授权范围。新旧选择及其指纹冻结后，旧集合独有资源使用明确排除贡献；该设备仍有其他有效来源时保留其精确窗口，没有有效来源时生成删除。贡献的资源级意图与来源代次均参与幂等核对，不能在分片重试中悄悄改变设备集合或窗口。

跨批次复用必须有持久且确定的执行归属，不能出现目标 A 等待 B、B 又等待 A。已经开始的尝试继续占据原资源顺序；尚未开始时按稳定规则选定执行者，其他逻辑目标复用其证据。历史已收敛墓碑保留审计，但不能占用当前有效来源上限，也不能因普通收敛而使当前期望指纹失效。

精确有效期以有效来源的区间集合表示，只能合并相交或相接的区间。设备仅支持一个区间而期望为多个不连续区间时，进入明确核验/能力限制，不能取最早开始和最晚结束扩大权限，也不能擅自选择一个来源而丢掉其他合法窗口。来源被撤销后，剩余期望与已应用窗口不同时须下发相应更新；只有已应用权限与保留依据一致时，才可直接以保留完成。

未知在途目标保留阻塞映射，租约超时不释放物理顺序。旧 ADD/DELETE 的可信结果仍保存；只有当前资源代次和当前来源快照相符才修改本地授权。旧结果影响当前期望时，生成有依据的补偿，其他主体和设备继续处理。多个请求共享物理目标时，通过来源贡献关联核验同一证据，批次按去重物理目标计数，请求按各自贡献收敛。

旧无绑定任务先查精确任务关联，再核对完整资源与历史别名。已接管、归属不唯一或不能证明安全的旧任务不能动态反查当前来源并删除；保留核验依据。只有能证明未触及新链路的旧任务才可走兼容收敛。新增、覆盖、重发、组织变化与所有撤权入口完成该保护后，才能开启统一批次入口。

设备回执阶段结束与业务来源收敛分别判定。工作流在精确可信当前事件的本地record完成，或可信迟到证据已持久保存且后继资源代次/补偿得到保障时，返回内部 `physicalSettled`；接入层核对event/attempt/target，并对该目标所有来源逐条聚合后，仅将本设备阶段置FINISHED。未返回、失败、不可信及任何来源尚未完成物理证据处理时仍保留阶段。target/request/source的CONVERGED依然要求全部必要设备与业务CAS完成，不能为停止轮询提前删除来源。部分人员/多页明细逐成员推进，结束的阶段不再轮询，其余继续；可信证据、补偿与阶段结束必须在同一事务中提交或回滚。

操作批次记录业务意图，目标记录协调后的物理动作，两者不要求相等。删除来源仍有共享权限时，必要的窗口调整以 ADD 目标表示；同批共享目标保留首次主请求，其他来源通过贡献关联，不能改写既有主请求。

来源意图同样独立于批次动作，仅接受 ADD/DELETE；一个批次可以包含撤销来源与保留共享来源，但每条来源和资源贡献仍须满足完整身份、代次及冻结指纹校验。结果事件的 CONVERGED 只表示本条可信目标证据对应的本地记录已原子写回；来源完成由请求状态独立记录，不能把最后一个来源完成标记当作每条目标记录都已处理的证据。

贡献 `BINDING_REVISION=0` 表示当前绑定；正修订保存旧 target/request/attempt 映射，负修订保存同资源旧 attempt 首次可信结果导致的补偿失效。运行后补偿使用独立批次和请求，不修改已冻结原批次的 expected，不重新受理伪造有效来源。已删除来源的墓碑仍可作为可信补偿删除的历史依据，但不能因此重回有效来源集合。

批内共享来源采用两阶段展开：先分页冻结并登记所有来源贡献，来源数和物理lane去重数分别保存；本批来源全部封口后，再逐物理lane计算完整期望并只建一个逻辑目标。不能在第一个来源尚未看到后续共享窗口时建立中间代目标，否则同一物理资源被重复计数并突破冻结expected。跨批次后续变化由独立补偿批次接续。

## 业务选择快照接入

PB员工/权限组入口在返回受理时冻结来源行、旧/新设备范围、凭据身份和精确窗口，来源稳定键仍为staffId+authId。批次snapshot只作摘要与关联，批量来源/资源明细使用按batch、稳定序号分页的持久选择表，不能每轮解析整批CLOB或重新查询已变更权限组。受理可以用数据库集合复制冻结明细，不创建设备任务、不做外部请求；具体查询与10k/20k受理耗时必须经本机Oracle实测。冻结后来源行及下发依据保持，等待版本门禁后的条件收敛。

选择表SMT_AUTH_SELECTION_SOURCE和SMT_AUTH_SELECTION_RESOURCE分别存每个来源的冻结业务投影与其资源INCLUDE/EXCLUDE投影；本机Oracle原验证26列来源表和15列资源表，通用投影增量后为32列和18列，合成结构位于`authoperation/selection-schema.sql`。主键/唯一键含batch归属，来源数与物理lane去重数精确校验。入口不得只传一个可变SQL查询条件当作稳定选择。未展开的已受理来源也须有可查询的待处理标记，旧收敛路径不得绕过它删当前来源。人员最小快照仅保存姓名、性别等必要字段，图片保留引用；不把本机结构视为生产迁移完成。

## 接入阶段的持久关联

ISC 的配置受理和下载受理是两个外部阶段，均须保留真实任务号，不能覆盖配置号后失去历史关联。实施接缝增加按 attempt 与阶段唯一的持久阶段记录，保存园区、接入实例、提交意图、实际请求关联、外部任务号、阶段状态、时间与核验原因；记录只保存本阶段有界摘要。实际表列和索引待接入模块合成 Oracle 验证后冻结。通用 attempt 的 ISC 外部批次号用于最终下载回执关联；在此之前由阶段记录保存配置受理及可能已提交的未知状态，不能用伪造任务号或设备成功事件填补。

每个尝试关联明确的原任务和直连命令流水；旧尝试映射永久保留。阶段开始先持久化再发起 HTTP，崩溃或响应缺失进入核验，不能在重启后直接重复提交。阶段状态与任务、attempt 的相应状态变更须原子保存，外部请求不进入数据库事务。已绑定新链路的任务由新调度消费，旧调度与旧来源同步均须通过绑定和已受理选择保护，防止双消费与动态反查误删。

## 调度额度与公平性

接入实例由显式配置将园区映射到实际共享的 ISC 实例或直连接入组；不得把每个园区默认视作独立 ISC 容量。启用园区必须有唯一、完整的实例映射。实例的速率额度和轮转游标持久化，多个调度进程使用同一短事务预留额度，不能各自重置内存令牌而叠加限流。外部执行在事务结束后进行；未知在途仍占用相应额度，不能用租约到期当作执行结束。

园区与接入类型到实例的映射还须有数据库唯一约束，避免不同进程以不同实例ID绕开共同额度。首次登记与实例状态、领取同事务，同实例重放幂等，冲突实例拒绝调度且不覆盖归属。运行中变更实例归属需要显式运维迁移，不能随配置自动抢占旧实例的在途工作。

迟到外部响应只有在持久接入阶段证明实际受理、归属完整且外部号不冲突时，才可补登记该历史尝试原先为空的真实外部标识；不得改变旧尝试状态、租约或任何当前目标。后续匹配的旧可信结果按版本规则触发补偿，不能因历史尝试缺号而永久丢弃已发生的设备副作用。

撤权、新增和回执分别保留处理预算，空闲预算可以有上限借用；新增在途不能占用撤权保留槽位。每轮先按实例、园区、设备轮转选择有界候选，再条件领取准确目标，不能先从大设备取满任务再在内存过滤。展开、提交、配置进度、下载回执和恢复扫描各自有页数及工作预算；任何一个耗尽不能阻止下一轮其他队列。所需调度状态表的列、索引和实际额度在合成 Oracle 及容量测试后回填，规划参数不视作已满足 SLO。

HTTP工作项按实例、园区和通道隔离，并有全局线程及排队上限；单个慢园区不能占用所有实例同通道的唯一执行线程。园区在途、园区速率及设备速率与实例额度共同预留。调度选择精确phase与设备、提交短事务后，接入端仅执行该组已预留phase；配置进度与下载发送分别计费，不能在接入函数内额外扫描其他未预留设备。参数须经容量验证，不把增加线程数视作吞吐已达标。

园区与设备层同样保留删除和新增在途槽位，不能只有实例总额度有保留。当前修复的本地初始配置为实例总400；园区总125、删除保留25、新增保留10；设备总25、删除保留5、新增保留2。这样新增仍可使用原100/20上限，同时留出删除空间；配置显式设置旧总量100时仍严格遵守100，不能静默超限。已有未知任务不因超时释放槽位，配置参数仍待容量验收。

配置进度和回执选组须包含本轮被选中的业务优先级种子，不能选中DELETE后又按旧ID读到另一ADD组。HTTP超时必须覆盖连接池等待、连接和整个响应读取，并实际取消请求和释放连接；只设置逐次read timeout或让外层Future超时而后台请求继续执行，均不足以保护调度槽位。

实际Timer展开须在单轮步数、每批轮转片及墙钟预算内持续处理，保存已消费游标；读到批次尾可在当前预算内回绕一次，不应隔轮空转。大批新增的来源封口规则保持，小批删除必须能轮转获得展开机会；直接调用stage/bind的测试只能定位服务与SQL成本，不能替代真实Timer节奏验收。

发送同样需要有界连续推进：每个园区通道工作项最多推进8个独立领取/执行单元，500ms只控制是否启动下一单元；每次重新领取租约和分层配额，不提高既定速率、在途或线程上限。准备完成但尚未消耗HTTP可在本tick继续领取发送；工作项显式失败、未知、退避或无实际推进立即结束，不能忙等配额。混合组中已持久核验的未知成员不妨碍其余健康成员推进，未知成员仍占在途且不得重发。该增量已通过限定验证；万级测试暴露的绑定查询瓶颈仍在修复，容量未验收。

ISC人员资产与设备授权分开核对：跨设备首次建人采用稳定实例与主体的持久owner，未知建人不能换设备重发。只有同operation、完整规范人员投影一致且核对真实ACCEPTED PERSON及可信身份归属，消费者才引用身份；不复制消费者PERSON成功阶段。创建者PERSON携带自己的照片，其余attempt分别上传FACE。该增量169离线与28项Oracle通过；随后修复并发父配置失效的异常路由，171离线及限定复审通过，28项Oracle属于修复前的结构和SQL基线。照片引用目前可在原imageCode上覆写，没有证明可恢复旧内容的不可变版本，因此不能只按imageId共享已上传证明，照片版本化不在本次通过范围。

恢复扫描只提供候选；恢复服务在主体锁内复核当前业务来源和资源代次，不能将正常新意图登记造成的代次前进当成迟到物理副作用。当前业务仍在展开或已有可信逻辑owner时先等待；真正旧证据使当前状态失效、且没有可推进的当前owner时再创建独立补偿。合法的BLOCKED、REUSE_PENDING和REUSE_APPLIED由工作流继续推进，不能统一归为冻结投影缺失。

## 通用来源的核验受理

服务器内部SourceSelection使用显式缺证据原因枚举；身份、父归属、园区、版本和非法凭据仍严格拒绝。设备证据缺失的真实来源可以零资源受理；完整真实资源坐标仅缺凭据时允许仅核验投影 `CREDENTIAL_VERSION=1/CREDENTIAL_SNAPSHOT=NULL`，部分原始事实保留于业务快照，不能伪造可执行v1或回落员工v0。一个家庭所在园区的整批进入VERIFYING，全部真实SOURCE保持PENDING，sourceCount计全量，expectedCount仅计已知去重资源、可为0，不把它当未知设备全集或成功数量。

原因、空凭据标记和业务核验事实参与幂等指纹，无原因的已有指纹保持原字节；受理、所有来源/资源与markVerification必须同事务成功。既有展开、封口、Version和pending门禁保持；核验批不生成虚构任务或进入成功。该增量不提供补证后自动恢复，也不允许新DELETE越过未完成ADD；这两个接缝须独立实现，不能靠更新冻结指纹或批次状态跳过。

### 未完成新增之后的撤权意图

采用有界串行后继：每个真实批准生命周期的根ADD来源最多有一个后继DELETE槽。撤权受理持久保存前置来源的批次、序号、完整指纹及本次全部可能暴露资源；受理本身不修改当前代次、不伪取消旧ADD，也不提前宣布撤权完成。旧ADD仍可能发送，只有所引用来源真实CONVERGED后才能激活DELETE；UNKNOWN或证据不足会让后继继续等待，须对用户显示待前置/待核验。此同一目标冲突不纳入健康独立撤权的首次下发时延指标。

激活时使用服务器生成的ExpectedPredecessor，在现有主体和来源锁内核对前置sourceId、generation、fingerprint、原行、intentKey、batchId及action，再按原协议生成下一代次。先处理同一完整intentKey及历史intentKey的精确幂等，再验证首次激活的前置，避免已成功stage但选择绑定失败或第二页重放被自身新代次挡住。未携前置的旧意图指纹字节与门禁保持不变；同键换前置必须失败。

等待不能用stageNext返回false表达，否则会被误当展开完成。实际调度扫描与stage直调均须区分正常等待和引用冲突；正常等待不推进批次游标/阶段，不累计失败或假进度，同轮其他健康批次继续。父预约到期覆盖先前局部OUT时，持久保存每条精确来源引用，可引用已有DELETE并仅为新增子集合创建批次；不修改旧批次expected，不用一个已完成批次代替完整scope。自动触发者与聚合请求引用的物理存储仍为独立接缝，未实现前不开放入口。

## 历史残留盘点的实施契约

盘点独立读取当前员工授权来源、ISC任务、ISC下发记录、直连任务、直连下发记录五个流。四张旧表以自身物理行为主，设备、员工、权限组和关联任务缺失时仍保存原行；task-only与downRecord-only不能通过内连接或按卡号去重丢失。员工卡类service 1/2/7保留原值，2只作APP完善疑点，不生成可发送FACE目标。当前来源的员工权限组资格独立绑定 `DeviceAuthTypeEnum.PERSON.getCode()`，当前为1；权限组TYPE=2是访客，不能和task的设备类型或service枚举混用。缺权限组、类型不符或不能证明员工归属时保留审计疑点，不伪造员工来源。

新增review与scan-flow两表：review保存有列集版本的完整已知原行canonical JSON CLOB、原行hash、完整查找证据CLOB及稳定指纹；原始与稳定证据变化生成新revision，旧正文不可覆盖，重扫相同内容只更新最后发现时间。稳定指纹排除采集时间，完整证据hash仍对应原CLOB；内容碰撞不能被当作幂等。仅保存图片引用，不收集图片正文、密码或令牌。生产列集尚未核实时RAW_COMPLETE不得假标完整。

每次run的五个flow分别持久化物理表ID高水位、ID/更新时间/完整重访游标、三个pass完成标记、租约令牌和行版本，每页最多200行。两张task表补低ID的更新时间扫描；缺更新时间的记录通过完整重访捕获修改。候选最后一行不必等于物理高水位，必须读到真实空页后CAS标记pass耗尽。review写入和游标前进同事务提交；失败整页回滚，旧令牌不可覆盖新worker进度。同FLOW_KIND仅允许一个READY/RUNNING/ERROR flow，以控制表函数唯一索引和flow行锁保护首次出现的legacyRef，不能依赖锁空结果集分配revision。

发现阶段的PHYSICAL_STATE始终UNKNOWN。平台表空、本地下发记录空或任务受理不能确认终端已删除；后续有可信且唯一身份、精确园区设备、无有效业务贡献及无未决新版本时，才可另行受理带legacyRef/revision指纹的补偿。宣布成功仍要求精确attempt/版本/外部标识对应的可信设备结果，盘点器本身不发送、重排旧任务或改变授权表。

读取列表只选受保护投影，不预加载CLOB。普通列表复用现有 `platform_auth_operation_review_view`，范围由当前SmartUser的园区集合在服务器计算；全局异常复用 `platform_auth_operation_global_review_view`，仅覆盖UNKNOWN/CONFLICT，不据空园区或管理员用户名放行全部KNOWN园区。敏感正文另需明确新增的 `platform_auth_operation_legacy_raw_view` 与同步追加的读取审计，审计提交前不返回正文；不能复用带target外键的治理动作表或把异步SysLog视为可靠读取留痕。实际UPMS授予与生产元数据仍未验证；当前首包只实施内部盘点与列表投影，API、同步读取审计和分段触发器接续完成。
