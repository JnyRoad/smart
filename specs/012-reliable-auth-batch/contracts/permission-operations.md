# 权限操作契约

## 已有 ISC 结果服务的第一阶段契约

`completeSuccess(task, remark)`：输入必须是已取得可信设备成功证据、原状态为 DOING 的持久任务。通过独立 Spring Bean 提供默认 REQUIRED 事务，按任务 ID、原状态和原 ISC 批次号条件更新 SUCCESS，然后维护下发记录；更新未命中或输入已终态时不重复处理；下发记录异常必须向调用方抛出并回滚。已有外层事务时参与该事务，避免后续来源收敛失败而提前提交任务成功。外部调用不得包在该事务中。

人员不存在、无下发数据、仅有平台权限项等证据不调用可信成功接口；新增与删除使用相同可信完成口径。旧接口公开签名保持兼容，内部迁移到该服务。

## 后续统一批次契约

- 受理：园区、幂等键、动作、来源、稳定目标选择；返回 batchId 和 PREPARING。鉴权及持久受理计入接口耗时。
- 展开：按批次游标领取有界分片；目标、任务关联、游标原子保存。版本冲突显式标记，不静默覆盖。
- 领取：按实例/园区/设备和业务队列额度选择可执行目标，返回 leaseToken；所有后续写入需校验归属。
- 提交：持久关联外部批次/命令号与目标版本，返回“受理”不返回“确认”。未知提交需先核验。
- 回执：携带接入、任务/尝试、目标版本、证据类别；持久化、幂等维护记录和来源收敛。
- 查询：服务端园区过滤，分页批次和目标，状态计数包含未展开项。
- 重发：仅目标未确认部分；旧在途尝试保存接管映射。
- 人工清理：核验依据、操作人和时间必填；不覆盖原始设备证据。

外部标识按实际接入核对：ISC 使用返回的配置/下载任务号，直连使用实际命令流水号；适配器必须保留所处阶段及原始标识，不能伪造另一类编号来满足通用接口。未知接入或缺少该接入所需标识时保持待核验。

待核验不删除尝试归属，后续可信回执仍可关联并推进；已终态目标收到不同事件也须保留证据，当前状态不能被旧失败结果降级。执行租约用于排他提交，不能同时充当删除历史回执关联的开关。

进度中的未完成数包含尚未展开目标和已确认但尚未本地收敛目标；失败数量单独展示并仍属于未完成。仅实际收敛完成和具备有效来源依据的保留目标计入完成数。结束展开必须同时核对受理时冻结的预期数、持久展开数和实际目标数，调用方不能降低预期数掩盖漏项。

管理接口的批次、请求、目标和尝试 ID 按字符串传输与保存，前端不得转为 JavaScript Number。现有公共 Jackson 已对 `Long` 包装类型配置字符串序列化，新 DTO 保持该口径。队列阶段时间明确使用带 UTC 标识的时间表示，不能让前端把无时区的 UTC 值解释为本地时间；业务授权有效期继续沿用既有契约。

物理路由、DTO 和状态数值在数据库阶段接入前冻结；第一阶段不新增无人调用的公开接口。

批次 `action` 保存业务操作意图，目标 `action` 保存协调后的实际设备动作。撤销某来源后若其他来源仍有效但窗口变化，该批次内允许生成物理 `ADD` 更新剩余精确窗口；不能为了动作与批次相同而误删共享权限。设备动作必须经版本协调核对，所有动作的目标均关联请求。多个来源在同一批次引用相同物理目标时保留各自请求/贡献，目标主请求不被后续来源替换。

来源 `action` 也独立于批次动作，且仅允许 `ADD` / `DELETE`。覆盖与撤销操作可以同时登记被撤销来源和仍有效的共享来源；各来源的身份、园区、代次、冻结指纹及资源 INCLUDE/EXCLUDE 仍须逐项核对，不能因放开动作相等要求而放松归属。

## 工作流与实际业务的事务接缝

受理有独立事务入口 `accept`，以及供业务选择冻结调用的 `acceptWithinTransaction`（REQUIRED）。选择明细、待处理标记和批次受理须一起提交或回滚，不能在外层业务事务回滚后留下孤立批次。

领取在调用者没有事务时执行并先提交。`prepareWithinTransaction` 将实际任务创建与尝试绑定放入同一短事务；外部调用必须在该事务提交后发生。`submittedWithinTransaction` 将已受理的真实外部标识与接入阶段证明一起登记。`receiveWithinTransaction` 将当前可信回执、版本应用、目标本地记录写回放入同一事务；独立调用使用 `receive`。实现共用私有核心，不能依靠同类自调用触发事务传播。

`TargetEvidenceHandler` 处理每个当前可信目标的本地任务及下发记录，输入包含 binding、eventId、taskId、物理动作、当前资源期望与来源快照。只有本条证据可信且版本允许应用时才能调用；返回 false 或抛异常须全部回滚。事件 `CONVERGED` 表示该事件的目标本地写回已完成，重复事件不得再次执行回调。请求的 `CONVERGED` 独立表示整个来源完成；只有全部资源已确认，`ConvergenceHandler` 才按稳定来源快照条件更新或删除业务行。这些回调不允许 HTTP、Feign 或按当前卡号反查后删除。

未提供目标记录回调时，只保留可信证据，不能自动完成来源或目标。共享来源的复用、资源确认和来源结算均要求当前资源代次存在可信成功事件且 `CONVERGED=Y`。一个物理目标关联多个冻结来源时，所有贡献绑定同一尝试，并用同一个原始事件逐来源处理；记录回调只执行一次，不能伪造多个设备事件。

以上为实施接入契约；真实入口、双接入和完整批量调度分别验收，工作流测试不能代替它们。
