# Feature Specification: 内部开放接口恢复 server 授权

**Feature Branch**: `fix/restore-oauth-server-scope`  
**Created**: 2026-09-05  
**Status**: server 恢复与照片园区校验已实现，待 PR 合并，未部署  
**Input**: 旅途要求内部使用只管理 server，并放开 PR #161 已收敛的权限。

## User Scenarios & Testing

### User Story 1 - 简化应用授权 (Priority: P1)
管理员新建或编辑内部应用，只需选择 server，无需逐项管理照片、能耗权限。
独立验收：新建 server 应用和既有应用增加 server 均可保存；新建选项只提供 server。

### User Story 2 - 内部调用恢复 (Priority: P1)
持有 server 客户端令牌的内部调用方可访问照片及能耗投影开放接口；调度默认申请 server。
独立验收：两个照片入口及四个能耗入口接受 server，关闭历史兼容开关也不影响 server。

### User Story 3 - 存量平滑维护 (Priority: P2)
已授予细分权限的应用可继续维护；默认历史兼容开启时仍可调用原接口。
独立验收：照片细分权限不能调用能耗接口，反之亦然；原令牌撤销机制保持有效。

### User Story 4 - 照片下载园区隔离 (Priority: P1)
用户已批准补齐下载校验：客户端只可下载自己园区内有效入厂申请关联的随行人员照片。
独立验收：同园区有效照片返回 200；跨园区、无园区授权、失效申请和无关联照片返回 404，且拒绝时不读图片。

### Edge Cases
匿名、用户令牌、错误或空 scope 不得访问开放接口；客户端令牌不得访问未开放路由。
历史细分/未知权限仅允许当前持有应用保留；关闭兼容仅影响历史细分权限。

## Requirements

### Functional Requirements
- **FR-001**: server 为正常可授予权限，新建及编辑应用均可使用；新授权不再要求或推荐细分权限。
- **FR-002**: PR #161 涉及的照片和能耗投影入口以 server 为长期授权，不依赖迁移开关。
- **FR-003**: 保留存量照片及能耗细分 scope 的精确兼容，默认开启；禁止跨能力通配放行。
- **FR-004**: 调度默认申请 server，旧显式细分配置可继续用作兼容；不强改真实环境或数据库。
- **FR-005**: 保留客户端身份认证、未开放接口默认拒绝、现有待拉取清单的园区过滤、密钥管理及授权变更后的令牌撤销。
- **FR-006**: 蓝图记录本次方向变更、PR #161 历史及真实交付状态。

- **FR-007**: 下载仅使用 token 的 app_park_ids，禁止请求参数扩大范围；server 和历史照片 scope 均遵守该边界。
- **FR-008**: 目标 photoId 必须关联随行人员及获授权园区内审批通过、未过期的非车辆申请，授权通过后才读取图片；空范围或无有效关联统一 404。

### Key Entities
- OAuth 应用：授权 scope 仍使用原存储结构，不进行数据迁移。
- scope 目录：server 为正常授权；既有两个细分权限作为历史兼容项。

## Success Criteria
- **SC-001**: 新应用只需维护 1 项通用服务授权即可调用本次覆盖的 6 个开放入口。
- **SC-002**: 覆盖匿名、错误授权、用户令牌及未开放路由的负向用例全部保持拒绝。
- **SC-003**: 默认配置下已有细分应用无需立即改配；移除或变更授权后的旧令牌撤销用例通过。

- **SC-004**: 真实控制器、鉴权适配器和照片服务组合测试覆盖同园区、跨园区与空授权；查询契约回归验证照片及申请条件和 Oracle IN 分批。

## Assumptions
用户已明确选择内部通用授权，接受持有 server 的应用获得上述开放接口访问权。
本次范围为源码、示例配置、回归与蓝图；用户已追加授权提交、推送并创建 PR。合并、部署及真实数据变更未授权。

## 审查发现与后续授权

server 恢复阶段的独立审查确认：基线下载仅校验 UUID 并按 photoId 读图片，没有 token 园区校验；最初只记录该既有风险。
用户随后明确批准补齐下载园区校验，本轮按 US4 / FR-007 / FR-008 修复，统一 server 授权保持不变。
