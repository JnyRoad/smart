# Feature Specification: 园区能耗评审缺陷修复

**Feature Branch**: `fix/energy-projection-review`
**Created**: 2026-09-05
**Status**: 已实现并通过本地验证，获授权提交 PR，未部署
**Input**: 旅途要求更新到最新基线，并修复上一轮评审的六项问题。

## User Scenarios & Testing

### User Story 1 - 系统读取园区月累计 (Priority: P1)
获授权的系统可读取所属园区当月从月初至调用日的水、电汇总；原后台用户查询继续工作。
验收：正确应用与园区成功，跨园区、空园区集合、匿名、错误授权及用户冒充应用均拒绝。

### User Story 2 - 总分表不重计 (Priority: P1)
指定了父表但父规则缺失的分表不被默认为有效纳入。
验收：缺父规则、父链断裂、循环、父表已纳入均有明确结果，不重复累计。

### User Story 3 - 自动补齐与可靠重算 (Priority: P2)
首次上线、历史错误修正及规则/倍率变更后，历史结果可以分批恢复；失败可重试且进度可见。
验收：超过单批上限继续推进而非等下一天；已有错误/过期事实重新处理；单表异常不伪报整批成功；实时任务不会被无界历史重算压住。

### User Story 4 - 授权变更失败可恢复 (Priority: P2)
修改应用授权后，即使认证服务暂不可用，旧客户端缓存不会被错误保留，旧令牌撤销可重试。
验收：异常分支缓存清理、再次提交相同授权、后台补偿及成功后的待办清理均可验证。

### Edge Cases
月切换、零表计、被删除表、非正数及超出园区整数范围的标识、缺失边界、无变化的正常事实、重复触发、处理过程中新增读数、依赖服务故障。

## Requirements

### Functional Requirements
- **FR-001**: 应用读取只允许获授权园区，保留后台用户查询，不改变通用 server 授权约定。
- **FR-002**: 无法解析的显式父级关系按异常处理，不把父子同时纳入。
- **FR-003**: 区分补缺和重算；错误、源数据或规则变化导致的旧结果可再次入队，活跃请求不得重复覆盖。
- **FR-004**: 初始化可在多次短任务中持续推进，保持有界单批预算、可恢复进度和实时处理机会。
- **FR-005**: 单表回算失败要持久化重试并返回可识别失败，不能仅记录日志后成功。
- **FR-006**: 客户端修改与令牌吊销失败需清缓存并有可恢复补偿，同一授权重试不能漏吊销。
- **FR-007**: 修复必须有先失败再通过的行为测试；生产部署、密钥改配和真实数据库操作不在本轮范围。

### Key Entities
月累计响应、园区授权集合、表计范围规则、表计日事实、投影队列、补齐进度、客户端撤销待办。

## Success Criteria
- **SC-001**: 应用读取的授权与拒绝矩阵全部通过，旧后台入口不回归。
- **SC-002**: 明确父子关系缺失场景不再出现父子双纳入。
- **SC-003**: 测试模拟跨批补齐、月切换、过期事实、单表失败及恢复，最终结果符合手工预期。
- **SC-004**: 授权修改故障与相同请求重试用例通过；进度及失败有明确输出。
