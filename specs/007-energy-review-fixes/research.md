# 研究与决定

- 采用现有 server + app_park_ids，保持 #183 的已批准方向；不用新的 read scope 恢复逐模块管理。
- 应用读取独立路由，避免在原用户方法上添加 @OpenApi 使用户令牌被拒绝。
- 显式父级缺失失败关闭，独立无规则表保持兼容。
- 补缺、重算和失败恢复沿用既有队列；短周期续跑避免把所有工作装进一次长 HTTP。
- 客户端缓存与撤销补偿显式处理，确保重复提交同 scope 能恢复故障。
- 真实 Oracle 计划、Redis 持久化配置、生产 app scope/URL 尚未验证；本地测试不代替现场验收。
## 授权补偿持久化修订

原考虑复用 Redis 待办。实现自审确认 PREPARED→数据库保存→READY 的跨存储窗口无法安全闭合：保存前就重试可能提前清待办，等待 READY 又会漏掉保存后进程退出的变更。因此采用客户端数据库同事务 outbox，不引入新服务/依赖，只增加一张撤销待办表。后台按版本删除，避免旧重试清除新授权变更的待办；成功前必须先失效共享客户端缓存。
