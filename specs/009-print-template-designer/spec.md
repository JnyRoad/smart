# Feature Specification: 厂牌与访客模板设计器

**Feature Branch**: `feat/pdfme-template-designer`

**Created**: 2026-09-05

**Status**: 单面独立模板兼容修订已完成；已补充系统持久关联与正式员工按职级匹配，相关业务管理与设备链路待开发。

**Input**: 旅途确认采用 pdfme；员工、外包及系统内其他人员厂牌使用正反两面，访客凭条只有一面；厂牌同时支持手动与自动翻面。本次按最新交互反馈改为每份模板只设计一面，双面通过关联或打印前选择两份模板组成，并调整规格与兼容验证页。最新确认：关联必须在正式系统中管理并持久保存；正式员工按员工级、职员级、经理级等职级使用不同模板，等级和对应关系由系统配置，不在代码中写死。最新补充：打印页同时支持自动匹配和手动选择；已发布的新模板即使未关联，也可手动选择后预览确认打印。

## User Scenarios & Testing

### User Story 1 - 后勤自助设计并管理模板 (Priority: P1)

后勤选择打印物类型，设计版式、绑定业务字段，保存后重新打开编辑；按分类管理，发布前预览校验，支持历史版本回滚。

**Why this priority**: 解决修改版式必须改程序的问题。

**Independent Test**: 不连接打印机，分别完成一套厂牌和一套访客模板的新建、编辑、保存还原、发布和回滚。

**Acceptance Scenarios**:

1. **Given** 新建人员厂牌正面或背面模板，**When** 打开设计器，**Then** 每次只显示当前模板的一张画布，独立布置文字、照片、背景、二维码及条形码，保存后可独立重开。
2. **Given** 新建访客凭条模板，**When** 编辑和预览，**Then** 只提供单面画布，输出恰好一面。
3. **Given** 已发布的单面模板及引用它的正反面组合，**When** 单独发布新版或回滚，**Then** 历史版本不可覆盖，组合仍引用原来两份具体版本；只有显式更新组合才影响未来任务。
4. **Given** 已保存两份合法单面厂牌模板，**When** 关联为正反面组合或打印前分别选择，**Then** 预览按正面、背面顺序展示；两份模板可以有不同版本号，兼容的组合可复用同一背面模板。
5. **Given** 超长姓名、必填缺失或元素越界，**When** 预览或发布，**Then** 指出问题，不通过增加页面容纳内容。

6. **Given** 管理员在系统模板管理中保存正反面组合，**When** 关闭设计器、刷新、重新登录或服务重启，**Then** 有权限的操作员仍能读到同一组合及其两份版本；画布只负责单面设计。

### User Story 2 - 按人员职级和单位自动选择模板 (Priority: P1)

系统依据园区、打印物类型、人员分类及公司/供应商绑定取得唯一有效模板。自动匹配正式员工时还必须按人员数据中的职级匹配，如员工级、职员级、经理级；职级与正反面组合的关联由后勤在系统中维护，可让多个职级共用同一组合。

**Why this priority**: 防止类别错印或遗漏保密凭条二维码。

**Independent Test**: 合成员工、外包和访客数据验证唯一匹配、无匹配和冲突。

**Acceptance Scenarios**:

1. **Given** 外包单位已绑定模板，**When** 选择该单位人员打印，**Then** 自动使用对应模板并校验打印物与设备兼容；人员厂牌缺少合法已登记卡号时拒绝打印。
2. **Given** 保密供应商访客缺少可用带码模板，**When** 请求打印，**Then** 拒绝并提示配置缺失。
3. **Given** 同优先级绑定冲突，**When** 保存绑定或解析模板，**Then** 阻止歧义配置或停止自动匹配；操作员仍可手选合法模板核对后打印。

4. **Given** 员工级、职员级、经理级分别关联不同厂牌组合，**When** 选择这些正式员工打印，**Then** 系统自动解析各自组合，界面展示职级和匹配依据；不得仅因同属 EMPLOYEE 使用统一厂牌。
5. **Given** 该职级没有有效规则或自动规则存在歧义，**When** 自动匹配，**Then** 提示未能自动确定模板并提供手动选择，不自动套用其他职级模板；缺失或未知的人员职级仍须先补齐资料。
6. **Given** 员工职级发生变化，**When** 再创建自动匹配任务，**Then** 使用新职级对应组合；已经创建的任务仍使用原职级及冻结版本。
7. **Given** 新模板已发布但忘记关联，**When** 在打印页切换手动选择，**Then** 可选择未关联的正面与背面模板（访客只选一面），无需先保存组合或适用规则；核对预览并确认后可打印。
8. **Given** 已有自动推荐或未关联的手选模板，**When** 操作员手动改选，**Then** 展示人员职级、实际模板名称/版本及两面预览；说明未关联或与推荐不同，确认后按实际选择创建任务，记录选择方式和操作员，不自动改写系统关联。

### User Story 3 - 手动翻面打印双面厂牌 (Priority: P1)

操作员逐卡完成正面、人工翻面确认和背面打印，界面持续显示当前人员与两面预览。

**Why this priority**: 兼容未安装翻面模块的证卡机。

**Independent Test**: 模拟器验证进度与重复提交；无自动翻面配置的实机验证同卡两面。

**Acceptance Scenarios**:

1. **Given** 手动双面任务，**When** 提交正面，**Then** 只打印当前卡的一面；确认正面已出卡后提示按校准方向翻面。
2. **Given** 等待人工翻面，**When** 点击「已翻面，打印背面」，**Then** 使用当前人员和模板快照打印背面；重复点击不重复发送。
3. **Given** 批量选择多个人员，**When** 执行，**Then** 逐人完成两面，当前卡未处理完时不开始下一张。
4. **Given** 刷新、客户端重启或背面异常，**When** 恢复，**Then** 保留两面的确认进度；结果不确定时先核对实卡，不自动重打。

### User Story 4 - 自动翻面打印双面厂牌 (Priority: P2)

同一组正面和背面模板在已配置翻面模块的设备上自动完成两面，手动模式也使用这组选择。

**Why this priority**: 减少人工操作，兼容硬件升级；仍是完整交付必需能力。

**Independent Test**: 带翻面模块的实机验证同卡双面、方向、页序与异常反馈。

**Acceptance Scenarios**:

1. **Given** 已验证自动双面能力的设备，**When** 打印厂牌，**Then** 自动完成同一张卡的正反两面。
2. **Given** 翻面能力缺失或未验证，**When** 选择自动双面，**Then** 发送前提示改用手动，操作员确认后创建相应模式任务。
3. **Given** 任务已开始，**When** 管理员修改设备默认模式，**Then** 当前任务保持原模式，新任务使用新配置。

### User Story 5 - 访客单面打印 (Priority: P1)

访客按申请及分类规则，使用自助设计的单面凭条在指定标签机打印。

**Why this priority**: 覆盖门岗现有核心流程。

**Independent Test**: 普通/VIP、保密/非保密、主访客/随行人员分别验证单面和数据归属。

**Acceptance Scenarios**:

1. **Given** 合法申请和匹配模板，**When** 打印，**Then** 每位访客对应一张单面凭条，不进入翻面流程或生成空白背面。
2. **Given** 纸张、可打印宽度或颜色能力不匹配，**When** 预览或提交，**Then** 提示并阻止不兼容输出。
3. **Given** 随行访客某人缺少必填字段/照片，**When** 打印，**Then** 指出该人员缺失，不沿用上一人的数据。

### User Story 6 - 受控管理、验收和切换 (Priority: P1)

管理员在授权园区内操作；全部通道验收后统一切换，并有可演练的回退流程。

**Why this priority**: 防止跨园区泄露、重复出卡及未验收功能影响现场。

**Independent Test**: 权限反例全部拒绝；隔离环境完成切换与回退。

**Acceptance Scenarios**:

1. **Given** 无园区或操作权限，**When** 访问列表、详情、预览、文件、发布或打印，**Then** 服务端拒绝。
2. **Given** 尚未联合验收，**When** 现场使用旧入口，**Then** 旧打印行为保持现状。
3. **Given** 切换后异常，**When** 回退，**Then** 停止新链路任务创建并处理在途任务；恢复旧访客链路，无旧实现的新厂牌入口停用，不宣称旧链路承接全部新功能。

### Edge Cases

- 组合缺面、用途错误或尺寸不一致、长内容扩展额外页面、中文缺字、二维码越界。
- 并发编辑/发布/回滚、绑定过期或冲突，任务创建后人员/模板/设备配置变化。
- 正面已出卡但回执丢失、翻面确认后断线、缺卡/缺纸/色带耗尽/卡纸。
- 两个浏览器抢占同一手动打印机，人工放错卡/方向，取消时卡仍在设备内。
- 队列接受任务不代表实际出卡；自动模式也可能需要人工核对。

## Requirements

### Functional Requirements

- **FR-001**: 按园区、打印物类型、人员分类和正面/背面用途管理单面模板；每份模板及每次设计器编辑始终只有一张画布。厂牌打印输出由两份模板组成正反面；访客只使用一份正面模板。
- **FR-002**: 支持拖拽文字、图片/照片、背景、二维码及条形码，编辑位置、尺寸、允许颜色和字段绑定，保存后可还原。
- **FR-003**: 单面模板独立保存、发布、预览和回滚；已发布内容不可变，保留被组合或任务引用的历史版本。正面与背面拥有各自版本号，不要求一致；更新其中一份不会隐式替换既有组合的引用。
- **FR-004**: 发布和正式渲染时校验面数、尺寸、必填、边界、字体及码区；内容溢出报错，不增加页面。
- **FR-005**: 服务端按园区、打印物、人员分类、正式员工职级及公司/供应商关系解析唯一目标：厂牌为正反面组合，访客为单面模板。自动未匹配或歧义时不自动创建任务，允许切换手动选择未关联的已发布模板；两种方式均校验园区、打印物、人员分类、权限和保密带码要求。
- **FR-006**: 打印机档案保存单面/手动双面/自动双面默认模式、介质和方向校准；同一组正面、背面模板用于两种双面模式。
- **FR-007**: 自动双面在提交前校验已验证翻面能力；发送任何打印指令前确认模式，活动任务不得中途更改。
- **FR-008**: 手动双面逐卡执行正面、确认出卡、人工翻面确认、背面；每次只发送一面的单面任务。
- **FR-009**: 手动流程展示当前人员、两面预览和匹配设备校准的取放卡指引；当前卡未完成不得插入他人任务。
- **FR-010**: 任务在开始前冻结人员数据、每面的单面模板版本、可选组合标识及修订号、打印机配置、模式及各面输出，防止正反面错配；人员厂牌必须有该人员在授权园区的合法已登记卡号，缺失则拒绝，访客凭条不要求实体卡号。
- **FR-011**: 刷新、断线、客户端重启后恢复已确认进度；重复请求/点击不重复提交；出卡结果不明先人工核对，再续打、确认完成或作废，不自动重印。
- **FR-012**: 自动双面在同卡完成两面并验证方向/页序；两面都有可信完成证据或人工核对后才标记完成。
- **FR-013**: 访客只输出单面，覆盖主访客/随行及普通/VIP、保密/非保密分类；逐人校验数据，不沿用上一人的字段和照片。
- **FR-014**: 服务端按园区及操作权限控制模板、版本、绑定、预览、文件、设备、任务及恢复；打印客户端绑定其获准园区和打印机。
- **FR-015**: 审计模板变更/发布/回滚、各面提交/回执、翻面确认、异常核对、取消及补打；默认列表和日志不暴露完整人员快照。
- **FR-016**: 全打印类型及手动/自动模式联合验收后一次性切换，保留旧访客链路至少一个版本周期；回退不重放在途任务。
- **FR-017**: 模板库、字体、渲染器和厂商组件满足商用及部署许可，保留许可声明及组件清单。
- **FR-018**: IC 厂牌仅打印卡面；卡号读取登记沿用独立业务链路，本功能不写卡、编码或变更门禁权限。
- **FR-019**: 同一打印机任务串行并具有独占执行权；人工翻面等待期间保持占用，失联后不得因超时释放而自动开始另一张卡。
- **FR-020**: 使用受控字段、字体及资源，拒绝任意脚本、未授权远程资源和越权照片；正式打印数据由服务端确认。
- **FR-021**: 支持保存正反面组合，也支持打印前分别选择已发布的正面与背面版本；两者均校验园区、用途、适用范围、尺寸、方向及介质兼容。厂牌手动/自动模式都必须先确定完整两面，任务开始或等待翻面时不得改选；访客不允许背面。
- **FR-022**: 正反面组合及适用规则在系统管理页面中维护并由服务端持久化、鉴权及审计；刷新、重新登录或服务重启后仍有效。设计器只设计单面布局，打印页读取系统配置，不以设计器内存或浏览器本地存储作为关联事实源。
- **FR-023**: 正式员工按员工级、职员级、经理级等职级匹配厂牌组合；以经验证的人事字典稳定代码配置，允许多个职级共用组合，不硬编码等级名称、范围或模板。职级缺失或未知须补齐资料；规则未命中或歧义时停止自动匹配并允许手动选模板，不自动跨职级兜底。手选无需已有职级/公司绑定，展示实际职级及选择依据供核对；新任务冻结职级及选择来源，职级变化不改已有任务。

- **FR-024**: 打印页始终提供自动匹配与手动选择。手选列表包含权限范围内尚未关联的已发布模板，可选已有组合或分别选择两面，不要求预先保存组合/适用规则；访客只选一面。手选需展示人员、职级、模板名称及版本、单/双面预览和与自动推荐的差异，经操作员核对确认后创建任务。两种方式都保留发布状态、权限、分类、尺寸/介质、必填及保密带码校验；记录实际选择方式和确认人，本次手选不自动修改长期关联。

### Key Entities

- **单面模板与版本**：打印物、分类、正面/背面用途、单页布局、独立历史版本、启用状态和发布记录。
- **正反面组合**：有名称的正面版本和背面版本关联，包含适用范围、修订号和启用状态；修改引用不改变既有打印任务。
- **模板绑定**：园区、公司/供应商、人员分类、正式员工适用职级与有效模板组合的持久匹配关系。
- **打印机档案**：园区、设备身份、介质、翻面能力、默认模式和校准证据。
- **任务及面进度**：一人一张卡/凭条、冻结数据和输出、每面执行、人工操作及结果。
- **受控资源**：字体、背景、照片等引用与访问范围，关联模板版本/任务。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 后勤无需修改程序即可完成一套双面厂牌和一套单面凭条的设计、保存、重开、预览；全部基础组件还原，系统中保存的组合可在重新登录和服务重启后读回。
- **SC-002**: 正背面可独立发布/回滚，已有组合与任务仍使用原来两份具体版本；面数/尺寸/必填/越界/字体/码区反例均拒绝。
- **SC-003**: 同一组正面和背面模板以手动、自动模式分别连续完成各10位合成人员实卡样本；人员、两面、顺序、方向全部一致，二维码/条码全部可读。
- **SC-004**: 访客样本覆盖普通/VIP、保密/非保密、主访客/随行，共至少10张，全部单面且字段、照片归属正确。
- **SC-005**: 重复点击、回执丢失、断线、刷新、客户端重启、缺卡/缺纸/色带耗尽、卡纸用例均保留正确进度，无自动重复出卡或跨人配对。
- **SC-006**: 跨园区、无权限、伪造设备、篡改任务、未授权资源用例全部拒绝且不产生打印。
- **SC-007**: 新链路默认关闭；切换及回退各演练一次，无在途任务重复执行，必需验收全部通过后允许生产切换。
- **SC-008**: 新增组件均有可追溯许可，未知授权组件不进入分发包。

## Assumptions

- 批次1为独立单面模板管理、版本、正反面组合维护、基础设计器和预览；批次2为绑定解析、打印客户端、实机联调及联合切换。故事优先级不表示允许先切换部分现场业务。
- 用户确认访客设备 Brother QL-800；呈妍型号称 CS220，官方 CS-220e 作为候选档案，铭牌、Windows、驱动、介质及进卡方式在实机阶段记录，尚未验收。
