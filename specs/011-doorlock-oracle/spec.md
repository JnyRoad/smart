# Feature Specification: 裕慧家园门锁统一接入与 Oracle 数据基线

**Feature Branch**: `docs/doorlock-oracle-baseline`

**Created**: 2026-09-05

**Status**: 需求基线；本轮交付设计与任务，不表示代码、数据库或设备已上线。

**Input**: 用户确认将独立门锁能力完整并入裕慧家园，统一使用 Oracle；先完成实施规格、数据库设计及可验证的开发任务，再开发、隔离真机测试、最终全通信域切换。

## User Scenarios & Testing

### User Story 1 - 住宿变更可靠驱动门锁权限 (Priority: P1)

宿管只在裕慧家园办理入住、调宿、退宿；每项门锁权限变更都能追溯到住宿事实，失败和待确认不会被隐藏。

**Why this priority**: 先消除两套系统人员住宿状态与门锁权限不同步的根因。

**Independent Test**: 使用合成人员、房间与模拟设备完成入住授权、确认、退宿撤权闭环；重放事件、终止进程、注入迟到回执，仍能解释每项权限状态。模拟测试不替代现场验收。

**Acceptance Scenarios**:

1. **Given** 一名未入住员工，**When** 入住事务提交，**Then** 产生一次可恢复的授权请求；事务回滚则不产生请求。
2. **Given** 已受理授权但设备未确认，**When** 宿管查询，**Then** 显示待确认，不显示已生效。
3. **Given** 人员已退宿，**When** 收到先前新增钥匙的迟到成功回执，**Then** 不恢复其通行资格，进入撤销补偿或设备核验。
4. **Given** 同房换床、跨房调宿、定时退宿、批量导入、离职或床位管理，**When** 有效住宿发生变化，**Then** 走同一规则；同房换床不重复发放房间权限。

### User Story 2 - 管理员在同一后台管理设备与凭据 (Priority: P1)

宿管使用现有账号和园区范围，管理门锁、网关、型号、房间绑定、授权、凭据、记录和告警，不再登录独立门锁后台。

**Why this priority**: 完整替代独立后台，而不是只迁移几个页面。

**Independent Test**: 使用两个园区、只读和管理角色，逐项对照旧后台操作清单，验证写操作、导出及跨园区请求。

**Acceptance Scenarios**:

1. **Given** 旧后台已确认的页面操作，**When** 使用新 Web 页面，**Then** 查询、字段、按钮、弹窗、校验、分页和反馈可逐项对照；安全调整有明确差异记录。
2. **Given** 无目标园区权限的管理员，**When** 直接提交接口请求或导出，**Then** 后端拒绝，不依赖隐藏按钮防越权。
3. **Given** 设备不支持或尚未验证某种凭据，**When** 请求下发，**Then** 明确拒绝并说明能力限制。

### User Story 3 - 员工在 H5 管理本人的门锁能力 (Priority: P2)

员工使用现有 H5 宿舍入口查看本人门锁状态、受控查看或修改密码、执行经验证的身份校验流程。

**Why this priority**: 延续当前本人自助体验，不引入第二个登录入口。

**Independent Test**: 已入住、未入住、退宿、切换冻结及篡改他人工号等场景，均通过同一本人接口验证。

**Acceptance Scenarios**:

1. **Given** 员工已登录，**When** 请求携带其他人工号或设备编号，**Then** 不得读取或修改他人凭据。
2. **Given** 密码修改已受理，**When** 设备尚未确认，**Then** 显示确认中；离开页面或退出登录后不持久保留密码。
3. **Given** 无有效住宿或处于冻结期，**When** 操作门锁，**Then** 显示真实限制与帮助，不展示伪成功。

### User Story 4 - 历史数据完整迁移且可核验 (Priority: P1)

数据负责人将旧系统资产、授权、任务、记录和必要历史身份关系迁入统一数据库，能解释每条转换或异常。

**Why this priority**: Oracle 已是确认目标，迁移必须支持断点续跑和历史查询，不能丢失撤权所需设备映射。

**Independent Test**: 在隔离环境对同一合成或经批准脱敏数据集导入两次，比较行数、来源键、关联及状态；中断后续跑结果与一次成功导入一致。

**Acceptance Scenarios**:

1. **Given** 重复或空工号、跨园区绑定，**When** 导入，**Then** 进入显式异常清单，不自动挑第一条人员记录。
2. **Given** 同一批次重复运行，**When** 重跑，**Then** 不产生重复有效授权，也不触发设备下发。
3. **Given** 旧未完成任务，**When** 接管，**Then** 保存原始状态及版本依据，并分类核验；不得整表重放。
4. **Given** 历史密码或指纹，**When** 迁移，**Then** 按批准的安全及设备能力策略处理；不以数据库未导入推断锁内凭据已失效。

### User Story 5 - 全通信域安全切换与运行处置 (Priority: P1)

运维在开发、测试和演练通过后统一切换网关服务地址，任何时刻同一通信域只能有一个真实命令执行方。

**Why this priority**: 同一门锁可连接多个网关，单锁、单网关灰度不能证明隔离。

**Independent Test**: 在与生产隔离的通信域演练停止旧执行、最终迁移、全量改址与回读、恢复事件、异常处置及回退。

**Acceptance Scenarios**:

1. **Given** 新模块处于开发或影子验证，**When** 输入生产镜像事件，**Then** 不能向真实网关发送。
2. **Given** 切换冻结，**When** 办理住宿，**Then** 仅在可靠排队已验证时继续受理；否则暂停相关业务，不静默丢弃变更。
3. **Given** 新系统已经改变设备权限，**When** 评估回退，**Then** 先处理新增业务与物理权限差异，不能仅恢复旧数据库。

### Edge Cases

- 入住事务未提交即发生异步调用；快速连续入住、退宿和再次入住；旧事件晚于新事件到达。
- 多网关连接同一锁；网关地址已修改但旧连接或网关缓存仍有在途命令。
- 钥匙槽位被新凭据复用；下发成功但回执丢失；撤权后迟到新增成功；进程重启丢失内存等待上下文。
- 远程开门超时不得在数小时后的恢复任务中自动重放。
- 房间换锁或解绑不能丢掉旧设备待撤权记录；账号、园区或住宿变化必须使本人端缓存失效。
- MySQL 与 Oracle 的空值、时间、数值及排序语义差异；历史无更新水位、重复来源 ID 或不可解析日志。

## Requirements

### Functional Requirements

- **FR-001**: 最终新在线业务、命令和审计统一使用用户指定的 Oracle；旧 MySQL 不参与新系统在线双写。
- **FR-002**: 管理账号、角色、菜单和园区权限统一使用裕慧家园既有体系，不新增独立门锁登录。
- **FR-003**: 人员、园区、房间和住宿事实只有一套在线主数据；门锁仅保留必要引用、设备映射及历史快照。
- **FR-004**: 住宿事实与待处理门锁变更共同成功或共同失败，异常与进程退出不能静默丢事件。
- **FR-005**: 覆盖正常、批量、定时、离职、床位管理、人员身份转正及房间设备绑定变更入口。
- **FR-006**: 重复与乱序输入不得恢复已失效权限；处理以稳定人员身份、业务版本和事件编号关联。
- **FR-007**: 区分授权意图、每设备每凭据状态、命令尝试及真实设备确认，不用“已发送”代替“已生效”。
- **FR-008**: 下发、重试、取消、恢复和补偿可追溯；重启可恢复；未知物理结果进入核验，远程开门不得无条件重试。
- **FR-009**: 有效期、退宿和撤权优先约束后续发放；迟到新增成功、设备槽位复用有专门防护与验收。
- **FR-010**: 按已验证的网关、门锁型号及固件能力执行凭据管理，不依据旧文档或源码存在单独宣称硬件支持。
- **FR-011**: 门锁、网关、型号和房间绑定可管理，资产启停、连接在线及物理状态分别表达。
- **FR-012**: Web 覆盖旧后台八组管理操作并有逐项对版和安全差异记录，最终收敛重复入口。
- **FR-013**: H5 仅提供本人能力，身份由服务端登录态确定，受有效住宿、园区和凭据状态约束。
- **FR-014**: 密码和生物特征最小化处理，不把生产秘密、完整模板和原始敏感报文放入普通日志、URL 或持久浏览器缓存。
- **FR-015**: 迁移保留已确认范围内的完整历史，具有批次、来源键、水位、校验、失败明细和断点续跑；排除项须有明确理由和批准。
- **FR-016**: 映射保留设备侧钥匙编号及历史人员关联；数据异常不静默合并，不把旧库状态未经核验当作设备事实。
- **FR-017**: 演练导入与影子处理不得激活生产授权或触发设备发送；旧未完成任务必须逐项分类。
- **FR-018**: 正式接管以完整通信域为边界，停止旧执行并完成最终迁移和全量改址核验后才能放开新发送。
- **FR-019**: 切换前后具有明确应急通行、在途命令处理和回退边界；新系统产生变更后的回退必须处理增量差异。
- **FR-020**: 管理写入、导出、敏感能力使用和系统补偿均有可关联审计，并可定位积压、离线、撤权未确认与迁移差异。
- **FR-021**: 兼容旧执行仅用于切换前过渡；开发、冻结及影子阶段默认禁止新系统向生产发送，最终移除旧在线依赖。
- **FR-022**: 本轮资料明确区分设计完成、数据库实测、模拟验证、真机验证和正式切换；未验证项列责任、所需证据及阻塞范围。

### Key Entities

- 人员与住宿引用：稳定人员标识、房间、有效住宿及事件版本。
- 门锁资产与绑定：稳定设备和网关标识、型号能力、有效绑定历史。
- 授权与设备凭据：业务原因、有效期、凭据元数据、设备侧钥匙编号及确认状态。
- 命令与回执：操作、目标快照、尝试、结果证据、补偿及人工核验。
- 迁移账本与历史记录：来源版本、表、行、批次、水位、映射、异常及核验结论。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 约定的住宿变更入口清单全部有验收用例，任何成功业务变更均能追溯到门锁处理结果或明确的无需操作结论。
- **SC-002**: 回滚、重复、乱序、重启和迟到回执测试中，静默丢事件、错误恢复已撤权限及伪成功均为零。
- **SC-003**: Web 八组操作逐项有对版结论；本人端及园区隔离测试不允许读取或修改他人范围的数据。
- **SC-004**: 每条迁移源记录可归入成功、去重、转换、待处置或批准排除之一；未解释差异为零；重跑不增加重复业务效果。
- **SC-005**: 切换演练所有网关成员均有改址回读和执行方隔离证据，旧任务、在途命令、应急通行和回退决策均有记录。
- **SC-006**: 每项需求有对应任务和验证方式，未验证外部条件不会被标为通过，也不阻止与之无关的离线工作。

## Assumptions

- 延续已确认的 Web + 微信 H5 范围，不包含原生 App、新 `smart-client` 基座开发或重写现有前端技术栈。
- 本轮只交付设计资料、源码级盘点与实施任务；不执行 DDL、DML、真实迁移、部署或网关操作。
- Oracle 为已确认产品约束；具体版本、Schema、容量和生产执行规则必须以受控环境证据确认，不从驱动版本推断。
- 既有源码、测试及旧 UI 构建包是参考资产，当前运行版本和各型号设备能力须另行核验。
- 历史保留期、敏感凭据处置及现场切换窗口作为上线前证据项；不假定全量保留敏感原文或全部清空锁内凭据。
