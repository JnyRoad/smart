# Feature Specification: 保密供应商软删除

**Feature Branch**: `003-supplier-soft-delete`

**Created**: 2026-09-02

**Status**: Implemented（未合并）

**Input**: 蓝图 3.3：实现保密供应商软删除；当前系统已有的供应商相关功能必须同步排除已删除记录，已删除供应商不得显示在 UI。PDA 端逻辑后续实现，本次不改。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 删除不再抹除供应商历史 (Priority: P1)

管理员在保密供应商管理中删除一个名下没有在册人员的供应商。系统将该供应商及已被删除的人员历史保留为失效数据，而不是永久删除。

**Why this priority**: 删除操作必须先可追溯，才不会造成协议和人员关联的历史空洞。

**Independent Test**: 删除一条无在册人员的供应商后，验证该记录仍存在于数据存储中，但常规读取已无法取得它。

**Acceptance Scenarios**:

1. **Given** 一家供应商没有在册人员，**When** 管理员执行单条或批量删除，**Then** 供应商标记为失效且不被物理移除。
2. **Given** 一家供应商仍有在册人员，**When** 管理员尝试删除，**Then** 系统沿用现有拒绝规则，不改变供应商状态。
3. **Given** 一名供应商人员被删除，**When** 管理员再次查询该人员，**Then** 常规人员查询不返回该人员，但历史记录仍可保留。

---

### User Story 2 - 管理端不展示已失效供应商 (Priority: P1)

管理员查看供应商树、人员列表、选择器、导出和通知候选数据时，不会看到已删除的供应商或其人员。

**Why this priority**: 软删除如果只改删除动作、不收敛读取路径，失效数据会继续进入管理端操作流程。

**Independent Test**: 为已删除供应商构造关联记录，逐一调用现有供应商/人员读取入口，确认返回结果不包含该供应商或人员。

**Acceptance Scenarios**:

1. **Given** 一家供应商已失效，**When** 管理端加载供应商树或人员新增选择器，**Then** 该供应商不在候选项中。
2. **Given** 一家供应商或其人员已失效，**When** 管理端加载供应商人员列表、导出或到期通知候选，**Then** 响应中不包含失效数据。
3. **Given** 保密区订单关联了一家已失效供应商，**When** 管理端读取订单详情，**Then** 不返回该供应商当前的展示信息，且订单本身保持可查询。

### Edge Cases

- 批量删除包含有在册人员和无在册人员的供应商时，沿用当前行为：仅删除无在册人员的记录。
- 已删除人员不再阻止其供应商删除；仍在册人员继续阻止删除。
- 历史物理删除的数据无法由本功能恢复；本次只规范未来删除动作。
- PDA/扫码命中失效供应商的提示属于后续范围，本次不新增 PDA 接口或页面。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须为保密供应商及其人员记录保留明确的有效/已删除状态，默认新记录为有效。
- **FR-002**: 系统必须将现有供应商及供应商人员的单条、批量删除动作改为标记已删除，不得物理删除记录。
- **FR-003**: 系统必须保留供应商删除前的在册人员校验；有在册人员时仍拒绝删除。
- **FR-004**: 系统必须从所有现有管理端供应商读取路径中排除已删除供应商和人员，包括列表、详情、下拉选择、人员列表、导出与通知候选。
- **FR-005**: 系统必须在供应商关联的保密区订单详情中隐藏已删除供应商的当前展示信息，同时保留订单本身可查。
- **FR-006**: 数据库发布物必须可重复执行，并在没有已删除数据时提供安全回滚路径；不得在本次实施中执行生产数据库操作。
- **FR-007**: 本次不得实现或修改 PDA/扫码端的失效提示逻辑。

### Key Entities *(include if feature involves data)*

- **保密供应商**: 受协议期限和园区范围约束的供应商主记录；删除后保留为失效历史。
- **保密供应商人员**: 隶属于保密供应商的人员记录；删除后不参与在册校验或管理端展示。
- **保密区订单**: 可引用供应商的既有业务记录；供应商失效不得使订单丢失。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 针对一条无在册人员的供应商，单条与批量删除后，常规供应商读取入口均不返回该记录。
- **SC-002**: 针对已删除供应商及人员，管理端使用的树、人员分页、选择器、导出与通知候选五类读取结果均不包含失效数据。
- **SC-003**: 针对仍有在册人员的供应商，删除请求返回现有拒绝结果，供应商保持有效。
- **SC-004**: 针对已失效供应商关联的保密区订单，订单详情仍可读取，且不暴露该供应商当前展示信息。

## Assumptions

- 本次“供应商”限定为蓝图 3.3 所述的保密区供应商及其人员，不改基础资料中的普通供应商域。
- 已删除数据不在管理端普通 UI 中展示；审计/数据恢复由受控数据库操作处理，不新增历史查询界面。
- PDA/扫码失效文案与接口按用户指示留待后续实施。
- 生产 Oracle 的字段、索引和执行计划需在发布前由数据库负责人实证核对；本地不连接生产库。
